# 局域网网页端与巢况登记 · 设计共识

日期：2026-09-19。一句话：在现有 Windows 托盘常驻应用内嵌入 HTTP 网页端（受信网段白名单 + 访问令牌双闸，无密码），新增「巢况登记」（蚁后数/工蚁数/照片的阶段性快照）与 Pushover 应用内配置；备份从"单个库文件"升级为"含照片的数据包"。本方案已经用户逐条确认，相关决策已落 `docs/adr/0003`、`docs/adr/0004` 与 `CONTEXT.md`（术语：网页端/桌面端/受信网段/访问令牌/巢况登记/巢况照片）。

## 一、现状（代码事实，评审时的快照）

- 应用：Tauri 2 Windows 单机托盘应用 v0.3.0。前端 Vue 3.5 + TS + ECharts，无路由库无状态库；Rust 侧 17 个模块。
- 数据层：rusqlite 0.40 bundled，**单条全局连接 + Mutex 串行**（`src-tauri/src/lib.rs:46` `with_conn` 为唯一咽喉点，53 个 IPC 命令全部过它）。`journal_mode = DELETE`（刻意不上 WAL——"冷拷贝库文件即完整备份"是记录在案的取舍）。迁移链手写于 `db.rs:96`，v0→v6 前向单向、每步一事务、比程序新即拒。
- 前后端调用：**无传输抽象层**，约 55 处组件内直接 `invoke()` + 2 处 `listen()`（`db-restored`、`update-download-progress`）。
- 设置：SQLite `settings` 键值表（5 键，缺键回默认）；备份配置刻意放库外 JSON（`backup-config.json`，防整库恢复回滚备份设置——本方案的令牌存储沿此先例）。
- 备份/恢复：备份 = 锁内拷库文件；恢复 = staging 校验（integrity + **旧版备份在临时库上跑迁移链升级后复校**，`restore.rs:170`）→ pre-restore 快照（保留 3 份）→ 锁内原子替换 + 重连（`open_and_migrate`）。
- 无任何 HTTP 服务代码；Pushover 凭据只读环境变量 `PUSHOVER_USER`/`PUSHOVER_TOKEN`（`pushover.rs:48`），不落盘。
- 托盘/自启/单实例/更新器齐备；更新安装有禁写位 + 装前快照。
- 测试：Rust 297 例、前端 Vitest 255 例；CI = pnpm test → cargo test → tauri build。

## 二、需求动机（用户原话摘录）

> 我希望本程序还支持局域网内打开它提供的 webui，当然需要启动的时候设定只支持信任那一段的虚拟局域网段，但是就得自动读取本机有哪些局域网段给用户选择。因为我用虚拟局域网组网的，只有我能用和访问所以这个 webui 访问是安全的，不用密码。这样我在家不开电脑也可以记录喂养蚂蚁的情况。

> 然后我也希望增加一个设置，允许在设置界面设置使用 pushover 的信息，默认是读取系统环境变量，也可以自己单独设置。然后还加上一个新的参数配置，这一窝初始化入巢的时候是大概多少数量的蚁群，比如几只蚁后，多少蚂蚁。然后后续可以阶段性的登记这个信息。然后还可以上传照片，蚁巢当前的样子，因为一开始可能蚁巢很小，然后后续变大了或者换蚁巢了，也希望记录下来。

> 那么现在增加了这些新的数据结构，那么后续数据库的升级和还原需要考虑兼容性

语境澄清（已与用户确认）：「不开电脑」= 电脑常开但不解锁桌面，手机在虚拟网内直接访问；程序继续跑在本机，不引入新部署设备。

## 三、决策清单

### D1 网页端形态（反转既有决策记录 0001 的"无需局域网访问"前提）

- 同一 Tauri 进程内嵌 HTTP 服务；设置页新增「网页端」开关，**默认关**。
- 装新版后首次启动弹一次启用向导（选网段 → 生成令牌 → 展示完整可复制地址 → 加防火墙规则）；跳过则保持关，设置页随时可开。
- 桌面端功能一分不减；网页端是第二入口不是替代。

### D2 双闸安全模型（无用户名密码）

- **闸一·受信网段白名单**：端口全网卡监听，但只放行来自所选网段的连接。网段从本机网卡枚举给用户选，**多选**；100.64–127（CGNAT）段自动识别为虚拟网段并置顶标名（用户组网软件为 NetBird，接口 wt0）。枚举须过滤虚拟化噪音网卡（本机实测有 VMware×2、WSL、Hyper-V）。
  - 弃绑定单一网卡 IP 方案：开机自启时组网客户端常晚于程序就绪，绑定即失败；虚拟网 IP 变更也失效。由令牌兜底。
- **闸二·访问令牌**：首次启用自动生成随机令牌；设置页可看、可改、可一键重生成；改动瞬间展示完整可复制访问地址 `http://<所选网段上的本机IP>:<端口>/?token=<令牌>`。手机首次打开后令牌自动存浏览器本地、地址栏自动抹掉。
- 令牌存数据目录独立 JSON 文件（**不进库**）——整库恢复不回滚令牌，手机书签不失效（沿 `backup-config.json` 先例）。
- 不做 HTTPS：NetBird 隧道本身加密，令牌不会明文跑公网（前提是只勾虚拟网段；将来勾物理网段再议）。
- 防火墙：启用时自动添加"仅受信网段+该端口"的最小开口规则，弹一次 UAC。
- 无鉴权的边界已向用户摆明并接受：凡进入受信网段且持有完整网址的设备，拥有记录类功能的完整读写权限。

### D3 网页端功能面（记录、不管理）

- **有**：首页（窝卡片、超期标红）、打卡（补录/选食物/备注全套）、历史记录（翻查/改/删，两段确认照旧）、冬眠操作（开始/出眠/补录）、**巢况登记**（见 D7，含手机拍照上传）。
- **无**（桌面专属）：统计图表、窝的增删改归档、字典管理（操作/食物/地点）、备份/恢复/导出、更新检查、全部设置（含 Pushover 配置与令牌管理）。
- 7 个桌面专属命令（文件对话框/打开文件夹/落盘导出类）不出网。
- 首页与打卡面板做手机竖屏适配；不引入第二套界面。

### D4 并发与实时刷新

- 两端并发读写沿用既有单连接互斥锁串行；**不动 WAL**（保住"冷拷贝即完整备份"）。
- 同条记录并发编辑后写覆盖（单用户场景可接受）。
- 任一端写入后广播数据版本号：网页端走 SSE 收、桌面端走事件收，收到即刷新当前页。现有 `db-restored` 事件语义并入同一广播。

### D5 Pushover 应用内配置

- 优先级：**应用内填了用应用内 → 没填回落系统环境变量 → 都没则推送渠道未启用**。设置页标明当前生效来源。
- 两个输入框打码显示、可点开看明文；「发送测试」按钮照旧。
- 存 SQLite `settings` 键值表（新增键，无需迁移，缺键回默认——沿用现有容错）。随备份/恢复走。

### D6 数据库兼容纪律（对既有机制的核实结论）

- 新增 schema 走迁移链尾部追加 v6→v7，**只加新表、不动旧表结构**（巢况登记新表、照片元数据新表）。
- 旧库升级（启动时 `open_and_migrate`）、旧备份恢复（staging 上迁移后替换，`restore.rs:170`，有真实 v1 库测试覆盖）、未来版本备份拒绝、降级 fail-fast——四条均为现成机制，本方案只新增"数据包"格式分支。
- 回退路径：更新器装新版前的快照 + 恢复旧备份。

### D7 巢况登记（合并概念：数蚁口 + 拍照 = 同一次观察）

- 一次登记 = 日期 + 蚁后数（非负整数可空）+ 工蚁数（非负整数可空）+ 若干照片（可零张）+ 备注 + 「换巢」标记；估不准写备注（"约2000，目测"）。
- 入巢时的第一条巢况登记即该窝基线（不在 colony 表加列）。
- 永不参与提醒（观察非照料，不进维护操作清单）。
- 展示：窝卡片显示最新一组数 + 距上次登记天数；窝详情按时间成线；工蚁数趋势折线并入统计页（第一版不做，后置）。
- 手机网页端为核心使用场景（数一数、拍一张、写两句一个流程走完）。

### D8 照片存储与压缩

- 文件存数据目录 `photos/`（按窝组织），库内只存元数据（路径、归属登记、备注）；**不以 BLOB 入库**（库会从 MB 涨到 GB 级，保留 30 份的自动备份吃穿磁盘）。
- 入库前自动压缩：长边 2048px、JPEG 质量约 85，单张落数百 KB；**原图不留**（饲养档案不是相册）。
- 照片写库（元数据行）即算"当日新数据"，自动备份触发语义不变。
- 上传通道：桌面文件选择 + 网页端 multipart 上传（过令牌+网段双闸），大小设上限。

### D9 备份升级为"数据包"（改写既有领域定义，见 ADR-0004）

- 备份产物从单个 `.db` 变为"数据包"单文件（库 + photos/ 打包）；手动"安全备份"与自动备份产出同一种文件。
- 恢复认两种来源：**旧裸库**（照既有 staging 迁移链路，不含照片）与**新数据包**（解包→库走同一套校验→照片放回）；恢复摘要新增"含/不含照片"。
- pre-restore 快照同步升级为数据包快照（"恢复可反悔"对照片同样成立）。
- 恢复旧裸库时 `photos/` 保留不动（恢复动作绝不顺手删文件；库回滚后照片暂成无害孤儿）；恢复数据包时 `photos/` 被包内内容整体替换（整包替换语义）。
- 旧版本应用恢复不了数据包（其选择器只认 .db）——数据包只能被 ≥ 本版本的应用恢复，已接受。
- 每份备份体积变大（照片压缩后单张约数百 KB，100 张约 50 MB，30 份保留约 1.5 GB），靠保留份数设置控磁盘。
- 导出（CSV/JSON）与备份是两条路：导出补巢况数据，互不影响。

## 四、边界（明确不做）

HTTPS / 密码登录 / 多设备分布式部署 / 网页端任何设置与管理操作 / 统计图表手机版（后置）/ 原图保留 / 照片修图裁剪 / 窝基数超出"记录"面的任何功能。

## 五、环境事实（设计输入）

- 组网：NetBird，接口 `wt0`，本机虚拟网 IP `100.121.249.122/16`（NetBird 节点 IP 惯例稳定）；**手机已装客户端入网**。
- 物理局域网 `192.168.100.0/24`（默认不勾）。本机另有 VMware×2 / WSL / Hyper-V 虚拟网卡（枚举噪音，须过滤）。
- 主电脑 Windows 10 常开、托盘常驻即载体；用户已有群晖 NAS（灾备）与一台跑 SSH broker 的小机——本方案不使用它们。
