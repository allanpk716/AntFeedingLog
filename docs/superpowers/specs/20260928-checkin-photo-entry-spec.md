# 巢况·拍照·头像入口重设计 + PowerShell 闪窗修复 · 规格

日期：2026-09-28 · 状态：已评审收敛（两轮异构评审，保存契约阻断经修订解除）· 来源：用户 mock 定稿的设计共识（.xcheck/20260928-152617 → 153743，D1-D8 + rev1 契约补全）

## Problem Statement（用户视角）

想给蚂蚁拍张照片记录巢况（顺带换头像），得先知道"照片必须挂在一条巢况登记上"，再手填一条登记，再找到登记条目底部的小按钮——三道坎。空时间线更是无处下手；"时间线"长得不像时间线；完整登记表单里选不了照片；设置页「网页」tab 一打开还弹两个 PowerShell 黑窗。

## Solution（用户视角）

「📷 拍一张」一步直达：卡片菜单点一下（或时间线顶部主按钮）直接调相机，拍完自动登记到今天、头像即时跟随，数数/备注以后想补再补。时间线改成左轴视觉（今日高亮），完整登记表单里直接选照片一并保存，纯照片条目只显示照片。设置页不再弹任何黑窗。

## User Stories

1. 作为饲养者，我想在窝卡片「⋯」菜单点「📷 拍一张」直接调相机，拍完自动记为今天的巢况登记且头像立刻更新，以便随手记录不用填表。
2. 作为饲养者，我想在巢况时间线顶部点「📷 拍一张」（主按钮）得到与上一条相同的结果，以便从时间线里也能一步拍照。
3. 作为饲养者，第一次打开没有登记的窝时，我想看到显眼的「📷 拍一张巢况照片」占位按钮，以便知道从哪开始。
4. 作为饲养者，我想在「📝 完整登记」表单里直接选照片，保存时字段和照片一起落库，以便一次观察的两面一次记完。
5. 作为饲养者，我想给纯照片条目后补数数/备注（点「编辑」），字段没改完空着也能保存，以便补录不被"至少填一项"拦住。
6. 作为饲养者，我想在时间线里一眼看出时间流（左轴+节点、今天橙色高亮、换巢/基线标记挂轴旁），以便快速定位最近的观察。
7. 作为饲养者，同一天拍了多张时，我希望头像用最后拍的，以便头像永远反映最新状态。
8. 作为饲养者，我想往旧登记补照片的既有按钮照常可用，以便给历史登记补图。
9. 作为饲养者，我打开设置页「网页」tab 或保存网页端配置时不希望弹出任何 PowerShell 窗体。

## Implementation Decisions

领域模型不动：头像 = 最新登记的第一张照片（纯派生）；头像排序契约沿用既有 `ORDER BY nc.date DESC, nc.id DESC, np.id ASC`（同日取后建者），不改，仅补直测加固。

### 服务端：通用原子保存通道（核心）

- 纯核新函数 `save_checkin_with_photos(conn, photos_root, input: CheckinInput, uploads: Vec<PhotoUpload>)`：同一把库锁/同一事务边界内建登记行（含全部表单字段 date/queen_count/worker_count/moved_nest/note）+ `photo::attach_photos` 挂照片（沿用既有校验链：格式/尺寸/重编码/UUID 落盘）。事务性：照片落盘失败则登记不落（与 attach_photos 既有行为对齐——库行与文件失败顺序照既有照片管线编排）。
- 校验语义（照片算内容·新建径）：`uploads` 非空 → 表单字段可全空（纯照片登记合法，跳过 ensure_something_filled）；`uploads` 空 → 走既有 `ensure_something_filled`（字段至少一项，防呆不变）。
- 三个调用面同一通道：「拍一张」= 全空 input（date=今天）+ 照片；「完整登记带照片」= 完整 input + 照片一并原子落库；「完整登记无照片」= 既有 `save_checkin` 命令零变化。
- **更新径**：`update_checkin` 内容校验改为「数/换巢/备注全空 **且该登记库内无照片** 时才拒」——已有照片的登记字段全空可保存，与新建径语义一致。编辑弹窗不嵌入照片增删（照片增删仍走登记条目既有按钮）。
- 网页端 `POST /api/photos`：multipart 文本段 `checkinId` 缺省时 = 创建模式：补收文本段 `colonyId`（必填）与可选 `date/queenCount/workerCount/movedNest/note`（缺省 date=今天、其余空）→ 走新通道；带 `checkinId` 的既有行为逐字不变。成功后触发既有写后钩子（版本广播+自动备份；巢况不刷托盘）。
- 桌面端新 Tauri 命令（入参 colony_id + 可选字段 + 照片文件，`pickPhotoFiles` 后字节在手）→ 同一纯核通道；命名 `save_checkin_with_photos`，前端 `ipc.ts` 加对应包装。
- `netseg.rs list_nics` 与 `firewall.rs` 的 PowerShell 调用加 `#[cfg(windows)] creation_flags(0x08000000)`（CREATE_NO_WINDOW）；不改数据流。

### 前端

- `ColonyCard.vue`：「⋯」菜单**置顶**新增「📷 拍一张」；卡片层隐藏 capture input（网页端）/文件选择（桌面）+ 编排：选好照片 → 调新保存通道 → 成功轻提示「✓ 已登记到「窝名」· 头像已更新」（措辞可微调不改语义）→ 抛 saved 刷新。
- `NestCheckinDialog.vue`：
  - 顶部双按钮：「📷 拍一张」（主，同上一编排）+「📝 完整登记」（次，展开/收起原表单；原常驻表单改为按需展开）。
  - 表单内嵌照片选择区（File 暂存、缩略预览、可多选、≤9 张/15MB 预检沿用），保存走新通道一并上传；表单空提交前端拦截（至少填一项或选了照片）。
  - 时间线改左轴视觉：左竖轴 + 每条圆点节点、日期挂轴、今日节点橙色高亮、换巢/基线标记贴轴旁。
  - 纯照片条目无正文行（不显示「（未填内容）」占位），只显示照片 + 操作按钮。
  - 空时间线：大占位「📷 拍一张巢况照片」+ 次级链接「或做一次完整登记」。
  - 既有登记条目的「拍照/传照片/从相册选/编辑/删除」按钮保留不动。
- 轻提示遵守全局规范；操作反馈判定：拍照自动登记成功（窗不关视图不变）→ 轻提示；表单保存既有行为（弹窗内反馈）不变。

### 词汇表

CONTEXT.md「巢况登记」词条补一句「纯照片（只拍一张、数与备注全空）也是合法登记」——由用户随功能提交（词条文件在操作者工作区，夜链不代写）。

## Testing Decisions

- 纯核（Rust 内嵌测试）：新通道四向单测（字段+照片 / 仅字段走防呆 / 仅照片合法 / 字段照片双空拒）+ colony 不存在拒 + 事务性（照片失败登记不落）；`update_checkin` 两测（已有照片空字段可保存 / 无照片空字段仍拒）；同日两次「拍一张」头像取后一次（既有排序契约直测加固）。
- webui_server：`/api/photos` 创建分支（colonyId+可选字段段 → 建行+落盘+返回 NestPhotoMeta[]；缺 colonyId 拒）与既有 checkinId 分支回归。
- 桌面命令包装层：路由/同形薄测（实施票补齐，F5）。
- 前端（Vitest，组件同目录）：卡片菜单新项双端可见 + 拍照编排（mock ipc 断言调新通道参数）；时间线双按钮/表单展开/嵌照片选择/保存编排；左轴视觉类断言（轴/节点/今日高亮）；纯照片条目无正文；空态占位按钮；`ipc.ts` 新命令名进 cmdName 契约测试；`photos.ts` 创建模式 multipart 形状。
- 全量门槛：vitest 全绿、`vue-tsc` 0、cargo 测试（17321 端口类环境败例如实归因）。

## Out of Scope

- 头像模型/排序契约改动；冬眠流程；纯核其余行为。
- 编辑弹窗嵌入照片增删（照片增删仍走条目既有按钮；未来另行立项）。
- 纯照片登记删光照片后的空行处理（基线既有交界，本链不动；见 Further Notes）。
- 两次网卡查询合并/缓存（只修闪窗）；mocks/ 讨论稿文件入库。

## Further Notes

- 非阻断留档（评审 F4）：用户可通过既有按钮删掉纯照片登记的唯一照片，留下字段全空且无照片的登记行（防呆只在保存/更新径生效）。现状显示层有"（未填内容）"兜底、可再编辑或删除，容忍；未来可选：删至空拒删 / 级联删登记 / 词条明确容忍。
- 头像即时更新走既有 data-version 广播（写后钩子内建），无新增机制。
- 桌面端「📷 拍一张」文案统一；行为=打开系统文件选择框（桌面无相机，多选照片即多图登记）。
