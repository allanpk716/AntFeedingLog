# 易腐食物撤食提醒 · 实施 Spec（2026-09-19）

来源：`docs/superpowers/specs/20260919-perishable-food-retrieval-consensus.md`（评审定稿 rev1）+ 决策快照 D1–D19 + 问题记录 F1–F9。术语遵守根目录 `CONTEXT.md` 词汇表（撤食 / 易腐 / 待撤食 / 提醒类·登记类）。

## Problem Statement

饲养者会投喂面包虫、干虾仁等蛋白质或湿食。这类食物留在活动区超过约一天就会发霉，危害蚁群健康。当前工具只能记录"喂过什么"，无法在喂下这类食物后提醒饲养者按时收走残食——用户必须自己记着"昨天喂了面包虫，今天得收"。

## Solution（用户视角）

- 每种食物可以标记**易腐**并配一个**撤食间隔**（小时，预置默认：面包虫、干虾仁 24 小时；种子不易腐）。
- 喂了易腐食物，该窝进入**待撤食**状态：首页卡片的「撤食」块（常驻喂食块旁）从置灰变为可点；喂食提交时告知"将于 X 小时后提醒撤食"。
- 超过撤食间隔仍未撤食：撤食块变红，Windows 桌面通知与手机推送每天各催一条，直到打卡「撤食」。冬眠中的窝同样提醒（发霉不等人）；已结束的窝不提醒。
- 「撤食」是第五种预置维护操作，打卡方式与其它操作一致（默认今天、可补录、可备注）；撤一次视为清空该窝全部待撤食物。
- 设置里：食物页签配易腐开关与间隔（开易腐必须填 1–168 的整数小时）；通知页签有独立的「撤食提醒」开关（默认开，总开关仍管一切）；操作页签里撤食性质固定"跟随喂食"，停用撤食即整个功能关闭。

## User Stories

1. 作为饲养者，我想给面包虫这类食物标记易腐并设定撤食间隔，以便喂下后系统自动替我记着收残食的时间。
2. 作为饲养者，我喂了易腐食物后想在提交时看到"将于 X 小时后提醒撤食"，以便确认提醒已生效。
3. 作为饲养者，我想在超过撤食间隔后收到桌面与手机提醒，且每天提醒一次直到我撤食，以便残食不会留在窝里发霉。
4. 作为饲养者，我想在首页卡片喂食块旁一键打卡「撤食」闭环，且撤食块在没有待撤食物时置灰不可点、有待撤时正常、逾期时变红，以便一眼看出哪窝该收食。
5. 作为饲养者，我想补录几天前喂的易腐食物时不被立即轰炸（录入当轮不补发通知），但首页红态照常显示，次日起按每日催促口径提醒，以便补历史与防遗忘两不误。
6. 作为饲养者（升级用户），我想从旧版本升级后不被存量历史喂食误报轰炸（升级前的易腐喂食只标红、不推送），以便升级体验平稳。
7. 作为饲养者，我想给已经自建过「撤食」操作的旧库升级时功能照样生效（同名操作升格为预置、历史记录保留），以便不丢数据也不重复建操作。
8. 作为饲养者，我想在设置里独立开关「撤食提醒」，以便嫌烦时只关这一类而不影响其它提醒。
9. 作为饲养者，我想让冬眠中的窝照常收到撤食提醒，以便入眠前忘收的残食不会烂两个月。
10. 作为饲养者，我想在托盘悬停概要里看到待撤食提示，以便不开主窗口也知道有窝该收食。
11. 作为饲养者，我想让撤食记录出现在日历热力图、每周操作次数、记录流水与导出里，以便饲养历史完整。
12. 作为饲养者，我想停用「撤食」操作来整体关闭撤食提醒（历史记录保留），以便不需要此功能时不被打扰。

## Implementation Decisions

- **数据模型（schema v7）**
  - `food` 加 `perishable`（0/1，默认 0）与 `retrieval_hours`（可空；合法值 1–168 整数，应用层拒 0/负/非整数）；按名回填预置：面包虫、干虾仁 → 易腐+24h（改名过的预置匹配不到，接受）。
  - `care_action` 重建引入第三种性质 `follow`（跟随喂食）：进 CHECK、无建议间隔、不参与提醒/登记切换；插入预置「撤食」（sort=2，原 sort≥2 顺延）。
  - **迁移撞名（F1）**：旧库已存在同名「撤食」自建操作时，升格该行（性质改 follow、标记预置，id 与历史引用保留；停用态保持），**并同步置 sort=2、对现有 sort≥2 顺延 +1（F7）**，不重复插入。
  - **存量基线（F4）**：迁移写设置键 `retrieval_baseline_at` = 迁移执行时刻；全新安装不写（视为无非存量）。
  - `reminder_ledger` 加部分唯一索引 `(窝, 基准日) WHERE kind='retrieval_due'`，实现"每天至多一条"。
- **派生状态（待撤食）**
  - 某窝待撤食 ⇔ 最近一次含易腐食物的喂食记录晚于最近一次撤食记录。到期时刻 = 该次喂食时刻 + **min(该次所选易腐食物的撤食间隔)**（"同喂取最短"为 Q3+Q5 已确认语义下的设计推定，待用户追认——F2；未设间隔的易腐食物按不存在处理，仅作脏数据自愈兜底）。
  - 再喂易腐食物按最新一次重算；每窝至多一个待撤食状态，撤食一次清空；删/改喂食或撤食记录后状态自动重算；已发提醒不追回。
  - 编辑记录不刷新 `created_at`，其"存量类"分类不变（F9 边界口径）。
- **提醒引擎（新 kind：retrieval_due）**
  - 检查注入完整时刻（小时粒度比较），沿用既有 30 分钟轮询与台账去重；参与窝 = 活跃或冬眠（**不吃冬眠静音**），已结束不提醒。
  - **通知三分类（F3 字面口径 + F4 存量基线）**：①新鲜喂食（录入时未逾期）→ 到期后每日一条；②补录喂食（录入时已逾期）→ 录入当轮不补发，自录入次日起每日催促；③存量喂食（`created_at ≤ retrieval_baseline_at`）→ 永不推送，仅状态红与托盘概要。
  - **开放问题（不实施）**："补录永久静默豁免"（宽读）待用户二选一，未拍板前排除。
  - 通知文案："「窝名」该撤食了：M月D日 HH:mm 喂的面包虫已超过 N 小时"。
  - 设置：`notify_retrieval_enabled`（默认开）与总开关都开才发；该开关为唯一分类开关。
- **界面**
  - 首页卡片：撤食块常驻喂食块旁，三档（置灰不可点 / 正常可点 / 逾期红），无倒计时；点击走通用打卡面板（默认今天、可补录、备注）。
  - 喂食提交反馈按分类分支（F6）：新鲜 →"将于 X 小时后提醒撤食"（仅当所选易腐食物全部有有效间隔）；补录已逾期 →"已逾期，明起每日提醒撤食"；否则不给将来时刻的承诺文案。
  - 设置-食物：易腐开关 + 间隔输入；**开易腐时间隔必填（1–168 整数），关易腐自动清空并置灰（F5）**；后端保存同款守护（易腐但无有效间隔 → 拒收）。设置-操作：撤食固定"跟随喂食"标注、停用即功能关闭。设置-通知：「撤食提醒」开关。
  - 托盘 tooltip 概要纳入待撤食。
- **统计/流水/导出**：排查写死的操作清单，将撤食纳入日历热力图、每周操作次数、流水筛选与 CSV/JSON 导出（撤食是普通维护操作记录，自动管道为主）。

## Testing Decisions

- Rust（既有纯函数 + 可注入时钟惯例）：v6→v7 迁移（保数据/按名回填/撞名升格含 sort 归位/baseline 写入）；派生判定（min 取最短、最新重算、撤食清空、删改联动）；通知三分类（新鲜/补录次日起催/存量永不）；每日一条台账去重；冬眠/结束窝过滤；开关组合；tiles 三态。
- 前端（Vitest 组件/lib 测试惯例）：撤食块三态渲染与禁用点击；打卡面板提交参数；喂食反馈文案分支（含补录已逾期变体）；设置易腐必填校验矩阵（空/0/负/非整数/越界/关易腐清空）。
- 只测外部行为，不测实现细节；沿用仓库既有同类测试先例。

## Out of Scope

- 未到期倒计时/灰字显示（Q12）。
- 撤食面板食物明细勾选（Q13）；"撤食及时率"专属统计（Q14）。
- 打卡时临时勾选易腐（按次覆盖，Q3 否决）。
- 独立待办表 / 一次性通知闭环（Q2 否决）。
- 已结束窝的撤食提醒。
- **补录"永久静默豁免"（宽读）——待用户二选一（F3 活动约束），未拍板不实施。**
- **存量红态批量清零（"一次性视为已撤"）——新增功能未获采纳（F8），晨报列为可选。**

## Further Notes

- 升级后存量易腐窝会持续红态直到逐窝打卡撤食（无自动清零路径）——已知权衡，晨报请用户表态是否需要批量清零。
- 升级前 24 小时内真未撤的食物升级后只红不推（窗口极窄，接受）。
- 工作区另有两项未提交内容（CONTEXT.md 词条修改、评审定稿前的共识稿），夜链不捎带提交，合并后由用户处置。
- 短间隔同日再喂：当天已发过一条则同日新到期不重发、次日恢复（台账按日去重的既有边界，接受）。
