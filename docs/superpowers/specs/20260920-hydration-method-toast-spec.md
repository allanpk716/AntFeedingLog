# 规格:巢穴保湿按窝细调(保湿方式)与全局操作反馈标准(轻提示)

> 日期:2026-09-20 · 决策出处:用户会话四轮确认(D1~D9)+ 评审链 20260920-123129/124140(F1~F6,详见 Further Notes)· 术语遵守 CONTEXT.md 词汇表

## Problem Statement

- 每窝蚂蚁的巢穴保湿节奏不同:水塔窝看水位即可(半个月甚至一个月补一次,或不提醒),手动加水窝约 7 天就得补一次。现状里巢穴保湿全局是登记类永不催促,想给某窝开提醒只能去窝编辑自己想数字;界面上没有"这窝是水塔还是手动加水"的表达,默认天数全靠脑记。
- 设置页点「保存」没有任何成败反馈(成功静默、失败是弹窗内红字),备份、导出、行级停用/启用/删除等"做完界面不变"的写操作同样没有反馈,且全项目没有统一的反馈标准,后续开发各做各的只会更乱。

## Solution(用户视角)

1. 编辑或新建窝时,巢穴保湿多一个**保湿方式**选择(未设/手动加水/水塔):选手动加水自动填 7 天、选水塔自动填 15 天,数字随手可改;已有周期的窝绝不被预填覆盖;只有显式清回"未设"才会连周期一起清空。升级前已设过保湿周期的窝原样保留提醒。
2. 设置页「操作」tab 顶部一行常驻小字提示"各窝可单独设每窝周期",让这个能力被看见。
3. 所有"操作完成后界面没有天然反馈"的写操作,屏幕底部弹一条自动消失的**轻提示**:成功绿色约 2.5 秒、失败红色约 5 秒带原因可点 × 关,同屏至多 3 条。关窗/列表即时变化这类有天然反馈的不弹;字段校验错误仍贴字段旁;催办提醒照旧走系统通知渠道,永不进轻提示。桌面端与网页端同一套。

## User Stories

1. 作为饲养者,我想给手动加水的窝自动得到约 7 天的保湿提醒,以便不忘补水。
2. 作为饲养者,我想给水塔窝设 15~30 天周期或不提醒,以便按自己的节奏检查水塔。
3. 作为饲养者,新建窝时我想顺手选好保湿方式,以便不用建完再编辑一次。
4. 作为饲养者,升级版本后我想保留已设好的保湿每窝周期,提醒行为不变。
5. 作为饲养者,改窝名等与保湿无关的编辑保存后,我想保湿配置原样不动。
6. 作为饲养者,我试探性选了个方式又改回"未设"时,不想因此丢掉库里的周期。
7. 作为饲养者,保存设置时我想看到"已保存"或失败原因,以便确认操作结果。
8. 作为饲养者,备份、导出、行级停用/启用/删除等操作完成后我想有反馈。
9. 作为饲养者,我不想被重复打扰:校验错误贴字段旁,催办走系统通知,互不混用。
10. 作为饲养者,换巢后改保湿方式时,我想保留自己调过的周期数字(只有空着才预填)。
11. 作为饲养者,网页端和桌面端的操作反馈长得一样。

## Implementation Decisions

### 数据与迁移
- SQLite schema v11:colonies 表新增 `hydration_method` 列(可空文本枚举:'manual'=手动加水 | 'tower'=水塔 | NULL=未设,默认 NULL);迁移幂等,**不触碰 colony_action_interval 任何行**——升级前已设保湿周期的窝自然形成"未设+已有周期"的存量 B 态。
- 读取链路(list_colonies 等既有命令)带出 hydration_method;既有每窝周期字段与 `interval_from_colony` 语义原样不变。

### 保湿周期状态矩阵(四持久态 × 九规则)
持久化状态(方式, 周期)四组合全部合法且可长期稳定存在:
A 未设+无周期(今天的安静窝) · B 未设+有周期(存量态,提醒照常,UI 方式列显示"未设"、周期照常显示) · C 方式+有周期(正常提醒) · D 方式+空周期(有标签不提醒)。

用户动作 → 落库语义:
1. 打开编辑窗:按库内现状原样回显,**不自动预填**(B 显"未设+数字",D 显"方式+空")。
2. 显式选择方式(未设→手动/水塔):周期框为空 → 预填默认(手动 7/水塔 15);非空(含 B 态已有周期) → 不动。
3. 未保存期间切换方式(手动↔水塔):框内值仍是本次会话预填值(未被手工改过) → 更新为新方式默认;已手工改过或为库内已有周期 → 不动。
4. 显式清回未设:方式置未设并**删除该窝保湿周期行**(唯一由方式动作触发删周期的路径)。**净零语义(F4 钉死)**:删周期效果以"库内方式原值非未设"为前提;库内原值=未设的会话内"选了又改回"净效果为零(B 仍 B)。库内 C 态清回未设时,周期输入框同步清空并置灰,删除后果可见。
5. 未触碰方式的编辑保存:方式与周期原样往返(B 仍 B、D 仍 D),改名字等无关编辑绝不影响保湿配置。
6. 只清天数:删周期行,方式保留(C→D)。
7. 新建表单:方式默认未设;未选方式不预填不落周期;选了方式周期框预填默认(可改,切换方式按规则 3 跟随)。**空框切换(F5 钉死)**:D 态空周期框直接切换方式时,空框即预填新方式默认(与"周期为空时预填"一致)。
8. "已有周期"专指已落库的周期行;输入框里的预填建议值保存前不算,不构成"永不覆盖"的保护对象(那是规则 3"手工改过"分支管的事)。
9. 已清空的天数不会在任何后续打开中自动复活;已手工改过的周期不会被任何方式切换覆盖。

### 写入原子性(F2/F6 钉死)
- 新建:"建窝+保湿方式+初始保湿周期"**同一条后端命令、同一事务**;任一步失败整体失败,窝不落库。
- 编辑保存:**整窗单事务**——基础字段(名字/物种/地点/日期/状态)+ 方式变更 + 周期增删一次提交;"清回未设+删周期行"必须原子。
- 失败语义:整体不落库 → 失败轻提示(红、带原因);不存在"窝建了但周期没落""方式清了但周期还在催""名字落了但保湿没保存"的半截状态。
- 历史的 create-then-set 两步 IPC 模式不用于保湿方式相关写入;其余操作的每窝周期读写维持现状,不强制改造。

### UI
- 窝编辑「周期提醒」小节:巢穴保湿行变为"方式下拉(未设/手动加水/水塔)+ 天数输入",其余操作行保持纯数字输入;选择器旁一句说明让"选方式→预填→可改"可懂(文案实现定)。新建表单带方式选择(周期随建随落)。
- 卡片零改动(不显示方式);窝编辑仍桌面专属,网页端不加管理入口。
- 设置页:「操作」tab 顶部常驻提示行"同一操作各窝节奏不同时,编辑某个窝可单独设「每窝周期」,优先于此处的全局设置"(文案可润色语义不变);"仅登记"下拉 tooltip 补全为"只记录,本页不催促;单个窝仍可在窝编辑里设周期提醒"。

### 轻提示(Toast)模块
- 全局唯一模块:store(成功/失败 API,自动消失计时,同屏≤3 条、更早先走)+ 组件挂应用根;桌面端与网页端同一前端同享;各调用点只调用,不得自造提示样式。
- 形态:屏幕底部居中浮层,不挡操作区;成功绿约 2.5 秒自动消失;失败红约 5 秒、文案带原因、可点 × 提前关。
- 判定原则:**操作完成后界面没有天然反馈的(窗不关、视图不变)必须弹;有天然反馈的(窗关闭、列表即时变化)不弹。** 覆盖:设置保存、字典行级停用/启用/删除、安全备份、导出 CSV/JSON、清理孤儿照片等一切"改了不关窗"的写操作;新写操作照此判定。打卡成功(关窗)、删除记录(两段确认+列表即变)不弹。
- 例外与边界(F3 钉死):字段级校验错误维持字段旁内联红字;**非校验类失败(含设置保存失败)统一走失败轻提示,设置弹窗旧的内联失败红字撤除**;催办提醒走系统通知渠道,永不进轻提示。
- 其余面板(WebUi/地点/更新等)的写操作按同一判定原则审计接线:有天然反馈者不弹。

### 其他
- 默认天数写死:手动加水=7、水塔=15;不做全局配置项。

## Testing Decisions

- Rust(cargo test):迁移幂等与 B 态保留断言(升级不丢周期行);新建/编辑原子命令成功路径与失败回滚;状态矩阵落库语义逐规则用例(净零语义、空框、清回未设删行、未触碰往返)。
- 前端(Vitest,组件同目录 *.test.ts):colonyForm 纯函数九规则交互(预填/不覆盖/切换跟随/净零/空框);ColonyFormDialog 新建带方式、编辑回显;toast store 行为(成功/失败/堆叠上限/提前关/自动消失);设置保存成功与失败接线、行级操作接线、提示行与 tooltip 存在性;均测外部行为不测实现细节。仓库既有先例:ColonyFormDialog.test.ts、SettingsDialog.test.ts。
- vue-tsc 类型零错。

## Out of Scope

- 不为水塔/手动做硬逻辑(水塔窝照样可设周期)。
- 不给巢穴保湿单独开配置小节。
- 不做方式字典化/自定义,不做"巢型"通用字段。
- 默认天数不做设置项。
- 卡片不显示方式。
- 不改提醒引擎判定逻辑(每窝周期语义原样)。
- 存量 B 态不做迁移期强制引导。
- 其余操作(换水/喂食/垃圾清理)不做方式维度,其每窝周期读写不强制原子化改造。
