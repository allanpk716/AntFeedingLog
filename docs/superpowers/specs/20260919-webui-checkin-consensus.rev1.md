# 局域网网页端与巢况登记 · 设计共识 · 修订版 rev1

日期：2026-09-19。本版为修订版（第 1 轮），在原共识基础上补齐 19 条已查实的规格缺口（文末附修订记录映射），方向与原稿一致：在现有 Windows 托盘常驻应用内嵌入 HTTP 网页端（受信网段白名单 + 访问令牌双闸，无密码），新增「巢况登记」（蚁后数/工蚁数/照片的阶段性快照）与 Pushover 应用内配置；备份从"单个库文件"升级为"含照片的数据包"。相关决策已落 `docs/adr/0003`、`docs/adr/0004` 与 `CONTEXT.md`（术语：网页端/桌面端/受信网段/访问令牌/巢况登记/巢况照片）。

## 一、现状（代码事实）

- 应用：Tauri 2 Windows 单机托盘应用 v0.3.0。前端 Vue 3.5 + TS + ECharts；Rust 侧 17 个模块。
- 数据层：rusqlite 0.40 bundled，**单条全局连接 + Mutex 串行**（`src-tauri/src/lib.rs:46` `with_conn` 唯一咽喉点，53 个 IPC 命令全部过它）。`journal_mode = DELETE`（刻意不上 WAL——"冷拷贝库文件即完整备份"是记录在案的取舍）。迁移链 v0→v6 前向单向、每步一事务、比程序新即拒。
- 前后端调用：**无传输抽象层**，约 55 处组件内直接 `invoke()` + 2 处 `listen()`（`db-restored`、`update-download-progress`）。本方案的工程前提 = 引入统一调用层，桌面走 Tauri IPC、浏览器走 HTTP，同一套业务代码双模式复用。
- 设置：SQLite `settings` 键值表（缺键回默认）；备份配置刻意放库外 JSON（`backup-config.json`，防整库恢复回滚——令牌存储沿此先例）。
- 备份/恢复：备份 = 锁内拷库文件；恢复 = staging 校验（integrity + 旧版备份在临时库上跑迁移链升级后复校，`restore.rs:170`）→ pre-restore 快照（保留 3 份）→ 锁内原子替换 + 重连。
- 无任何 HTTP 服务代码；Pushover 凭据只读环境变量，不落盘。
- 测试：Rust 297 例、前端 Vitest 255 例；CI = pnpm test → cargo test → tauri build。

## 二、需求动机（用户原话摘录）

> 我希望本程序还支持局域网内打开它提供的 webui，当然需要启动的时候设定只支持信任那一段的虚拟局域网段，但是就得自动读取本机有哪些局域网段给用户选择。因为我用虚拟局域网组网的，只有我能用和访问所以这个 webui 访问是安全的，不用密码。这样我在家不开电脑也可以记录喂养蚂蚁的情况。

> 然后我也希望增加一个设置，允许在设置界面设置使用 pushover 的信息，默认是读取系统环境变量，也可以自己单独设置。然后还加上一个新的参数配置，这一窝初始化入巢的时候是大概多少数量的蚁群，比如几只蚁后，多少蚂蚁。然后后续可以阶段性的登记这个信息。然后还可以上传照片，蚁巢当前的样子，因为一开始可能蚁巢很小，然后后续变大了或者换蚁巢了，也希望记录下来。

> 那么现在增加了这些新的数据结构，那么后续数据库的升级和还原需要考虑兼容性

语境澄清（已与用户确认）：「不开电脑」= 电脑常开但不解锁桌面，手机在虚拟网内直接访问；程序继续跑在本机，不引入新部署设备。

## 三、决策清单

### D1 网页端形态（反转既有决策记录 0001 的"无需局域网访问"前提）

- 同一 Tauri 进程内嵌 HTTP 服务；设置页新增「网页端」开关，**默认关**。
- 装新版后首次启动弹一次启用向导（选网段 → 生成令牌 → 展示完整可复制地址 → 加防火墙规则）；跳过则保持关，设置页随时可开。
- 桌面端功能一分不减；网页端是第二入口不是替代。
- **端口策略**：默认固定 17321，设置页可改（1024–65535，合法性校验）；启动时端口被占用 → 服务不启动，托盘 tooltip 与设置页红字提示换端口；改端口后防火墙规则同步重建，手机去设置页重新复制完整地址。

### D2 双闸安全模型（无用户名密码）

**闸一·受信网段白名单**
- 端口全网卡监听，但只放行来自所选网段的连接。网段从本机网卡枚举给用户选，**多选**；100.64–127（CGNAT）段自动识别为虚拟网段并置顶标名（组网软件为 NetBird，接口 wt0）。枚举过滤虚拟化噪音网卡（VMware/WSL/Hyper-V）。
- **判定细则**：只认 socket 层来源地址（accept 得到的对端地址），**不信任任何转发头**（`X-Forwarded-For` 等一概忽略）；白名单按 IPv4 CIDR 匹配，**IPv6 默认拒绝**（本方案的网段均为 IPv4；将来需要再议）。
- **请求限制**：普通 API 请求体 ≤ 1MB、照片上传 ≤ 15MB/张、连接并发上限 8、读超时 30 秒、header 数与单条长度上限；超限即断开。绑定成功后服务只响应白名单内来源，其余来源 TCP 层直接关闭。
- **物理网段硬警示**：勾选任何非 CGNAT 段（如家里 192.168.100.0/24）时，选择器当场弹强制确认框，明示"该网段内令牌与数据将以 HTTP 明文传输，且该网段可能有多台非你控制的设备"；不确认不给勾。虚拟网段（加密隧道）不弹。
- 弃绑定单一网卡 IP 方案（组网客户端晚于程序就绪即失败、IP 变更失效），由令牌兜底。

**闸二·访问令牌**
- 首次启用自动生成随机令牌（≥128bit）；设置页可看、可改、可一键重生成；**重生成即旧令牌全量失效**（所有已授权浏览器下次请求被拒，需重新复制地址）。
- **令牌传递协议**（避免进浏览器历史/同步记录）：
  - 完整访问地址形如 `http://<IP>:<端口>/#token=<令牌>`——令牌放 **fragment**（`#` 后），不进浏览器历史条目、不随 query 发给服务器、不进服务端日志；
  - 页面首次加载后 JS 把令牌存浏览器 localStorage 并 `history.replaceState` 清净地址；
  - 之后所有 API 请求以 `Authorization: Bearer <令牌>` 头携带；
  - **SSE 专用短时票据**：EventSource 无法带自定义头（Web 标准限制），页面用主令牌调 `POST /api/sse-ticket` 换取 60 秒一次性票据，EventSource 以 `?ticket=<票据>` 建连；票据短时一次性，残留历史亦不可用；
  - 设置页在展示完整地址处附一行提示："地址含进门凭证，勿转发他人；若曾在浏览器历史中留下明文地址可用无痕模式或清历史，也可随时重生成令牌作废旧凭证"。
- 令牌存数据目录独立 JSON 文件（**不进库**）——整库恢复不回滚令牌，手机书签不失效（沿 `backup-config.json` 先例）。
- 不做 HTTPS：NetBird 隧道本身加密（前提：只勾虚拟网段；物理网段按上面的硬警示走）。
- **防火墙联动**：规则名固定（`AntFeedingLog WebUI`）、方向入站、限定"所选网段 + 当前端口"；改网段/改端口 → 删旧规则建新规则；关闭网页端 → 删规则；增删失败落错误流水并在设置页提示手动处理（附现成命令）。首次启用时以一次 UAC 授权自动添加。
- 无鉴权的边界已向用户摆明并接受：凡进入受信网段且持有令牌的设备，拥有记录类功能的完整读写权限。

### D3 网页端功能面（记录、不管理）

- **API 白名单，默认拒绝**：HTTP 层只暴露显式登记的端点集合——首页数据（窝列表+超期状态）、打卡（读字典/提交）、历史记录（查/改/删）、冬眠操作、巢况登记（含照片上传）、SSE 通道、sse-ticket、健康检查与数据版本号；**未登记命令一律 404 拒绝**（deny-by-default）。桌面端 53 个 IPC 命令不因此受限。
- 工程前提：引入统一调用层（桌面 Tauri IPC / 浏览器 HTTP 双模式），约 55 处直调机械改造，不引入第二套界面。
- **有**：首页、打卡（补录/选食物/备注全套）、历史记录（两段确认照旧）、冬眠操作（开始/出眠/补录）、巢况登记（含拍照上传）。
- **无**（桌面专属）：统计图表、窝的增删改归档、字典管理、备份/恢复/导出、更新检查、全部设置。
- 首页与打卡面板做手机竖屏适配。

### D4 并发与实时刷新

- 两端并发读写沿用既有单连接互斥锁串行；**不动 WAL**；同条记录并发编辑后写覆盖（单用户可接受）。
- 任一端写入后广播**单调递增数据版本号**；桌面端走事件、网页端走 SSE。
- **SSE 重连对账**：连接建立与每次重连时，服务端第一帧即推当前数据版本号；客户端与本地版本比对，落后即整体重拉当前页数据（而非只等增量事件）。锁屏/切网恢复后不依赖"错过的事件"。
- 现有 `db-restored` 事件语义并入同一广播。

### D5 Pushover 应用内配置

- 优先级：**应用内填了用应用内 → 没填回落系统环境变量 → 都没则未启用**；设置页标明当前生效来源。
- 两输入框打码显示、可点开看明文；「发送测试」照旧；存 `settings` 键值表（新增键无需迁移，缺键回默认）。
- **明文风险，明示接受**：凭据以明文存于库内，随数据包备份扩散到备份目录（含 NAS 上的灾备目录）。不用 Windows DPAPI 加密——DPAPI 绑定本机账户，加密后的数据包在换机/重装后无法解密，与 D9"数据包可携恢复"目标直接冲突；备份介质属用户自有资产，此残余风险已向用户摆明并接受。

### D6 数据库兼容纪律

- 迁移链尾部追加 v6→v7，**只加新表、不动旧表结构**（巢况登记表、照片元数据表）。
- 旧库启动迁移、旧备份 staging 迁移、未来版本拒绝、降级 fail-fast——均为现成机制；本方案新增"数据包"格式分支。
- 回退路径：更新器装新版前快照 + 恢复旧备份。

### D7 巢况登记（合并概念：数蚁口 + 拍照 = 同一次观察）

- 一次登记 = 日期 + 蚁后数（非负整数可空）+ 工蚁数（非负整数可空）+ 若干照片（可零张）+ 备注 + 「换巢」标记；估不准写备注。
- **修改**：字段级编辑（含日期）。
- **删除**：两段确认；**删除登记同时删除其引用的照片文件**（唯一引用，无别处留存）。
- **基线语义**：基线 = 该窝**最早一条登记的日期字段**；补录入巢情况时把首条日期改成入巢日期即可；删除首条后，下一条最早者自然成为基线。
- 入巢时的第一条巢况登记即该窝基线（不在 colony 表加列）；永不参与提醒。
- 展示：窝卡片显示最新一组数 + 距上次登记天数；窝详情按时间成线；工蚁数趋势折线后置。

### D8 照片存储与压缩

- 文件存数据目录 `photos/`（按窝子目录），库内只存元数据；**库内存相对路径**（相对 `photos/`，形如 `<colonyId>/<uuid>.jpg`）——换机/数据目录迁移后引用不失效。
- **落盘文件名一律服务端生成**（UUID），客户端原始文件名只作展示与备注素材，**不参与任何路径构造**（杜绝路径穿越与重名覆盖）。
- **写入协议（文件与库的一致性）**：
  1. 先写同目录临时文件 `photos/.tmp-<uuid>`，写入完成并 fsync；
  2. 原子 rename 为最终名 `<colonyId>/<uuid>.jpg`；
  3. 最后开库事务插入元数据行并提交。
  - **失败路径**：任一步失败即整体失败、报错给前端；rename 成功但插库失败 → 删除已落位文件再报错（不留半截状态）；
  - **触发语义**：自动备份的"当日新数据"以**元数据行提交成功**为准（`trigger_after_write` 在命令成功后触发的既有语义不变）——备份打包时库内引用的文件必然已完整落位；
  - 打包 photos/ 时跳过 `.tmp-` 前缀与进行中写入。
- **上传校验链**（桌面与网页同一套）：
  - 单张压缩前 ≤ 15MB；单次登记 ≤ 9 张；
  - 输入格式白名单 JPEG/PNG/WebP，**完整解码后重编码输出**（统一 JPEG、长边 2048px、质量约 85）——完整解码天然拒绝"截断伪装图"，重编码天然**清除全部 EXIF（含 GPS 定位）**，输出尺寸与体积受控（防解码炸弹落盘）；
  - 照片响应头：`Content-Type: image/jpeg` + `X-Content-Type-Options: nosniff` + `Content-Disposition: inline`，仅以图片身份渲染；
  - 原图不留（饲养档案不是相册）。
- **删除生命周期**：删登记 → 删其照片（见 D7）；**删窝（既有两段确认）→ 级联删除该窝全部巢况登记与 photos/ 下该窝子目录**；归档窝 → 全部保留（只是收起展示）。
- **孤儿治理**：库中无引用的照片文件（恢复旧裸库遗留、历史异常残留）在下次恢复/启动巡检时移入 `photos/.orphan-<时间戳>/` 隔离（**移动而非删除**）；设置页提供"查看并清理孤儿照片"入口（列出大小、确认后删除）。

### D9 备份升级为"数据包"

- 备份产物 = 单文件 zip 数据包：**根级 `manifest.json`**（格式版本、创建应用版本、创建时间、库文件名与 SHA256、照片清单：每张相对路径 + SHA256、总张数与总字节数）+ 库文件 + 照片文件（按相对路径存放，**打包时跳过 `.tmp-`/`.orphan-` 与库中无引用的文件**——清单驱动，孤儿不进包）。
- 手动"安全备份"与自动备份产出同一种文件；保留份数照旧控磁盘。
- **恢复协议**（认两种来源）：
  1. 旧裸库 `.db`：照既有 staging 迁移链路（不含照片）；恢复后 photos/ 内现存文件按 D8 孤儿治理隔离；
  2. 数据包：读 manifest → 格式版本检查（未来版本拒绝，同库 schema 纪律）→ **逐文件 SHA256 校验** → **磁盘剩余空间预检**（包内总字节 × 1.2 余量）→ 解包到暂存目录（路径白名单限定 photos/ 内、拒绝 `..` 与绝对路径——**防穿越**）→ 库走既有 staging 校验链（integrity + 版本迁移）→ pre-restore 快照（**升级为数据包快照**）→ 锁内替换库文件 → 照片按清单落位 → 广播刷新；
  - **中断恢复**：协议结构保证"先暂存后替换"——任何一步失败，当前库与 photos/ 均未被破坏（照片落位最后进行，逐文件 rename；中途失败的已落位照片属于"多余的文件"，不破坏一致性，下次巡检按孤儿隔离）；
  - 恢复摘要新增"含照片 N 张 / 不含照片"。
- pre-restore 快照 = 数据包（"恢复可反悔"对照片同样成立）。
- 恢复数据包时 `photos/` 被包内内容**整体替换**（先清后放，整包替换语义）；恢复裸库时 photos/ 不动（恢复动作绝不顺手删文件）。
- 旧版本应用恢复不了数据包（选择器只认 .db）——数据包只能被 ≥ 本版本的应用恢复，已接受。
- 导出（CSV/JSON）与备份是两条路：导出补巢况数据，互不影响。
