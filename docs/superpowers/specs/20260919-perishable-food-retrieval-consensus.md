# AntFeedingLog 易腐食物撤食提醒共识（2026-09-19）

用户提出：面包虫、干虾仁等蛋白质或湿食喂后若不隔天清理会发霉，希望喂食食物类型上有一个附加选择，喂了这种食物就生成定时清理提醒。
经两轮 14 问评审（Q1–Q14，其中 Q10 为用户自定义方案）+ 8 条惯例确认形成决议。本文记录决议与实施清单，不写代码。
配套词条已同步根目录 `CONTEXT.md`（新增：撤食、易腐、待撤食；修订：维护操作预置五种、提醒类/登记类的撤食例外注记）。

## 一、决议总表

| # | 问题 | 决议 |
|---|------|------|
| Q1 | 术语 | **撤食**（收走活动区没吃完的易腐食物；与「垃圾清理」=清垃圾区严格区分） |
| Q2 | 闭环模型 | **新预置维护操作「撤食」+ 派生「待撤食」状态**：不落库存任务，从喂食记录实时算出；打卡「撤食」即闭环。否决了独立待办表（要养新概念、撞"避免任务/待办"口径）与纯一次性通知（错过即丢、看不出"还有没收的食"） |
| Q3 | 易腐配置位置 | **食物字典项属性**：每食物一个"易腐"开关 + 撤食间隔（小时）。预置默认：面包虫 ✓、干虾仁 ✓（均 24h）、种子 ✗。否决全局固定"隔天"与打卡时手动勾 |
| Q4 | "隔天"语义 | **喂食时刻 + N 小时**（N 按食物配），30 分钟轮询内送达；不用"次自然日"（送达时刻飘忽，还要给引擎新增固定时刻概念） |
| Q5 | 未撤又喂 | **最新一次易腐喂食重算**；每窝至多一个待撤食状态、覆盖全部易腐食物，撤一次清空。已知边界：天天续喂永不逾期提醒——靠开盖喂食时肉眼兜底，接受 |
| Q6 | 逾期催促 | **每天一条直到撤食**（同现有超期节奏），首页持续红 |
| Q7 | 冬眠 | **撤食提醒不吃冬眠静音**（发霉不等人）；其它提醒照旧静音 |
| Q8 | 补录 | **进状态、不补发通知**：补录历史易腐喂食后首页照常标红，但不发桌面/手机通知 |
| Q9 | 通知开关 | **单列「撤食提醒」开关，默认开**。⚠️ 修正注记：评审时说"现有超期/冬眠两组分类开关"是错的——反馈第二轮 Q7/Q9 已删分类子开关，现状是单一总开关（`notify_overdue_enabled`/`notify_hibernation_enabled` 键留在库中但引擎与 UI 均不读，reminder.rs:284-285 只读总开关）。本决议新增的「撤食提醒」将成为**唯一**分类开关，总开关仍管全部渠道 |
| Q10 | 打卡入口（用户方案） | **撤食块常驻喂食块旁边、固定占位不跳位**，三档动态：无未撤易腐喂食 → 置灰不可点；有易腐喂食未到期 → 正常色可点；逾期未撤 → 红。否决了"只进打卡面板"与"红态才浮现"（位置跳动难成肌肉记忆） |
| Q11 | 设置性质 | 撤食性质固定「跟随喂食」：设置里**不显示**提醒/登记切换、无间隔可配；**停用撤食 = 整个功能关闭**（历史撤食记录照常保留展示） |
| Q12 | 未到期显示 | **无倒计时、无灰字**，撤食块可点即唯一在窗信号；只有逾期才红 |
| Q13 | 撤食面板 | **普通确认面板**（窝 + 撤食 + 时间 + 备注），食物上下文只在通知文案里；否决"列出明细可勾选"（撤食一次清全窝，勾选是假精度） |
| Q14 | 统计 | **默认融入**：日历热力图、每周操作次数、流水筛选自动出现撤食；不做"及时率"等专属图表 |

配套语义（8 条惯例，随评审确认）：

- 已发提醒不追回；删/改喂食记录后未发的按新事实自然重算（沿用改出眠日期口径）。
- 改易腐开关/间隔立即按新口径生效（间隔 24→12h，18 小时前喂的立刻逾期）。
- 间隔输入：正整数小时 1–168，0/负数拒收（沿用食物周期校验惯例）。
- 多窝各自提醒（沿用每窝每操作一条）。
- 托盘 tooltip 纳入待撤食（"2 窝活跃 · 大头一号待撤食"）。
- 喂食打卡提交成功时反馈一句"将于 X 小时后提醒撤食"。
- 出眠/入眠不清待撤食状态，只以撤食记录闭环。
- 食物停用不影响历史：停用"面包虫"后历史喂食照样参与派生。

## 二、实施清单（票 G1–G3，沿用 TDD）

依赖：G1（数据层）先行，G2（引擎）依赖 G1，G3（前端/设置）依赖 G1/G2 接口；顺序 G1→G2→G3。

### 票 G1：字典与数据层（schema v7）

**改动点**
- `db.rs:23` SCHEMA_VERSION 6→7，新增 `migrate_v6_to_v7`（单事务）：
  - `food` 加列 `perishable INTEGER NOT NULL DEFAULT 0 CHECK (perishable IN (0,1))`、`retrieval_hours INTEGER`（NULL = 未设；0/负数由应用层拒，同食物周期惯例）；按名回填 面包虫/干虾仁 → `perishable=1, retrieval_hours=24`（同 F2/F3"按名回填"边界）。
  - `care_action` 重建（v1 DDL 的 `kind` 带 `CHECK (kind IN ('reminding','log_only'))`，db.rs:300）：新 kind 值 `follow`（跟随喂食）进 CHECK；插入预置「撤食」`('撤食', NULL, 'follow', NULL, 1, is_preset=1, sort=2)`，现有 sort≥2 的操作顺延 +1；已存在「撤食」名（用户自建过）则不插、不动（同按名防重惯例）。旧库重建时旧行原样保留。
  - `reminder_ledger` 加部分唯一索引 `uq_ledger_retrieval (colony_id, base_date) WHERE kind = 'retrieval_due'`（v6 已去 kind CHECK，无需再动表）。
  - 全新安装的种子 INSERT（db.rs:259-268）同步：撤食进操作种子（sort=2，原 2-4 顺延为 3-5）、食物种子带易腐默认值。

**验收**
- 旧 v6 库升级：数据原样、面包虫/干虾仁带易腐 24h、撤食操作出现且预置不可删、台账旧行保留。
- 全新库：种子即含上述默认。

**测试**：v6→v7 迁移保数据、按名回填命中/改名不命中、种子断言、`follow` kind 通过 CHECK。

### 票 G2：派生状态与提醒引擎

**改动点**
- `care.rs`：
  - 新增派生计算：某窝**待撤食** = 存在喂食记录（经 `log_food` 关联）含 `perishable=1` 食物、其 `occurred_at` 晚于该窝最近一次撤食记录的 `occurred_at`；到期时刻 = 该次喂食时刻 + **min(该次所选易腐食物的 `retrieval_hours`)**（多种易腐同喂按最短算）。易腐食物未设间隔的按不存在处理（不参与、也不挡其它易腐食物）。
  - `tiles_for_colony`（care.rs:602）：撤食 tile 三态输出 `none / pending / overdue`（不占 `days_since`/`is_overdue` 通道，`is_overdue`（care.rs:138）对 `follow` 恒 false）。
  - `log_care`（care.rs:153）对撤食无特殊分支——闭环靠派生重算，天然覆盖删/改喂食、删撤食记录的联动。
- `reminder.rs`：
  - `ReminderKind` 加 `RetrievalDue("retrieval_due")`（reminder.rs:57-77），`notification_text` 文案："「窝名」该撤食了：M月D日 HH:mm 喂的面包虫已超过 24 小时"。
  - `compute_due_reminders` 签名注入**完整时刻 now**（现有 `today` 保留给日粒度类）：撤食到期用时刻比较；台账基准日 = 当前自然日，`uq_ledger_retrieval` 去重 → **每天至多一条**，随今天推进实现 Q6 的每日催促。
  - 参与窝 = 活跃 **或** 冬眠（Q7 不吃静音；已结束窝不提醒——归档即停管）。
  - 补录静默（Q8）：待撤食的**通知**条件额外要求该次喂食录入时未已逾期（`occurred_at + interval > created_at`，分钟级容差）；不满足则只进状态、永不发通知，直到下次新鲜喂食重置。状态与红态不受此限。
  - 设置过滤：总开关 + 新键 `notify_retrieval_enabled`（默认 true）都开才发（reminder.rs:284-285 处扩展）。
- `settings.rs`：`AppSettings` 加 `notify_retrieval_enabled` + `K_RETRIEVAL`（settings.rs:13-28、93-114 同款三处）。
- 托盘 tooltip 概要（lib.rs）纳入待撤食。

**验收**
- 喂面包虫（24h）→ 25 小时后检查：桌面 + Pushover 各一条、首页撤食块红；再过 24 小时未撤 → 又一条；打卡撤食 → 状态清空、不再发。
- 同喂 种子+面包虫+湿食(6h)：6 小时后即到期（取最短）。
- 冬眠窝待撤食照发；已结束窝不发。
- 补录 3 天前面包虫：块红、零通知。
- 改间隔 24→12：18 小时前的新鲜喂食立即逾期并发提醒。
- 删除该喂食记录：状态消失；已发的提醒不追回。

**测试**：派生判定（含多食物取最短、撤食晚于喂食则清）、补录静默、每日一条去重、冬眠/结束窝过滤、开关组合、tiles 三态、文案。

**验收**

**测试**：三态渲染与禁用点击、面板提交参数、反馈文案出现条件、设置校验（0/负/非整数/越界拒收）。

## 三、明确排除项

- 不做未到期倒计时/灰字（Q12）。
- 撤食面板不列食物明细勾选（Q13）。
- 不做"撤食及时率"等专属统计（Q14）。
- 不做打卡时的临时易腐勾选/按次覆盖（Q3 选了字典级）。
- 不做独立待办表与一次性通知两种闭环（Q2 选了派生状态）。
- 已结束窝不发撤食提醒（归档即停管，随 Q7 派生）。

## 四、风险与边界

- "按名回填"边界同 F2/F3：改过名的预置食物不带易腐默认值，需手动开（单人工具，接受）。
- 短间隔同日再喂：台账按 (窝, 当日) 去重，当天已发过一条则同日新到期不重发、次日恢复——默认 24h 间隔下不触发，接受。
- 通知送达时刻不挑时段（引擎半小时轮询，凌晨也可能推）——与现有超期提醒同款行为，接受。
- 桌面通知依赖应用在跑（托盘常驻缓解）；手机推送有 2 天补发窗口（`PUSHOVER_RETRY_DAYS`）——撤食提醒沿用，不单独放宽。
- "天天续喂永不逾期"漏洞（Q5 已接受）：开盖喂食时肉眼兜底。
