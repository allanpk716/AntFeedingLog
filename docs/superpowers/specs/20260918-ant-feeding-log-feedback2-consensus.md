# AntFeedingLog 反馈第二轮共识（2026-09-18）

用户实测第一版后提出 5 条反馈，经 10 问评审（Q1–Q10）形成决议。本文记录决议与实施清单，不写代码。
配套词条修订已同步进根目录 `CONTEXT.md`（新增：打卡、删除记录、统一周期、食物周期、通知渠道；修订：维护操作、食物、建议间隔、距上次）。

## 一、决议总表

| # | 问题 | 决议 |
|---|------|------|
| Q1 | 快捷打卡防误触 | 非喂食快捷操作（换水/保湿/清理）改为弹**打卡面板**：日期默认今天、可补录过去、可填备注，点"记录"才落库；喂食沿用现有 FeedDialog |
| Q2 | 喂食周期粒度 | **双层周期**：操作层统一周期（距上次任何喂食）+ 食物层各自周期（距上次喂该食物），任一超期即提醒；预填 种子 3 / 干虾仁 7 / 面包虫 7，新食物默认不设周期 |
| Q3 | 通知渠道 | **双通道**：Windows 桌面通知保留 + Pushover 手机推送新增（修订自最初的"只留 Pushover"——避免单点故障） |
| Q4 | Pushover 凭证 | 只读系统环境变量 `PUSHOVER_USER` / `PUSHOVER_TOKEN`；设置页不做输入框，只显示检测状态；改环境变量需重启应用 |
| Q5 | 字典预置项保护 | 默认四操作 + 默认三食物**禁止删除**；改名 / 停用 / 改周期自由 |
| Q6 | 首页删除入口 | 不加；删历史记录走记录页（已有两段确认删除） |
| Q7/Q9 | 通知开关结构 | 只留**一个总开关**（管两渠道全部提醒）；删掉"超期提醒""冬眠提醒"两个子开关；保留提前天数与测试按钮 |
| Q8 | 推送失败 | 未送达的手机推送由下一轮调度（≤30 分钟）补发；超过 2 天作废 |
| Q10 | 双通道配合 | **并行双发**、互不依赖；一个渠道挂了另一个照发 |

配套语义：

- 喂食砖块红态 = 统一周期超期 **或** 任一设了周期且超期的食物超期；悬停 tooltip 列各食物"距上次"。
- 喂食与食物周期都**没有**"提前 N 天预警"——超期当天起提醒、每天最多一条（现状不变）；提前天数仍是冬眠出眠专用。
- 冬眠中的窝静音对两层周期同样生效。
- "发送测试通知"同时发桌面 toast + Pushover 各一条，分渠道回显结果。

## 二、实施清单（票 F1–F4，沿用 TDD）

依赖关系：F1、F2、F4 相互独立；F3 最大、建议殿后。F2 与 F3 共用同一个"按名回填"迁移边界（见各票）。

### 票 F1：快捷打卡面板（纯前端）

**改动点**
- `src/components/ColonyCard.vue:61-90`：`onTile` 对非喂食操作不再直接 `quickLog`，改为打开新组件 `QuickLogPanel.vue`（新建：日期 datetime-local 默认 `nowLocalDateTime()`、备注 textarea、"记录/取消"按钮）。
- 提交仍走现有 `log_care` 命令——后端零改动（`happened_at` / `note` 已支持，`ensure_not_future` 拒未来日期）。
- 喂食路径不动（FeedDialog 已是面板形态）。

**验收**
- 换水/保湿/清理点击弹面板；点"取消"零落库。
- 日期改到昨天 → 补录成功；改到明天 → 被拒并提示。
- 备注可填可空，落库后记录页可见。

**测试**：组件测试——取消不触发 invoke、提交参数正确（colony/action/日期/备注）、未来日期报错路径。

### 票 F2：字典预置项禁删

**改动点**
- 迁移：`care_action`、`food` 各加列 `is_preset INTEGER NOT NULL DEFAULT 0`；对已存在的库按**名字**回填（四操作名 / 三食物名）；`src-tauri/src/db.rs:162-171` 的预置 INSERT 直接带 `is_preset=1`。
- 后端守护：`erase_action`（dict.rs:212-241）、`erase_food`（dict.rs:322-341）最前面加 `is_preset → Err("预置项不能删除；可改为停用")`。
- 列表 SQL（dict.rs:107-112 及 food 对应处）带出 `is_preset`；前端 `SettingsDialog.vue:360-362` 删除按钮 `disabled` 条件加 `row.is_preset`，title 文案同步。

**已知边界（接受）**：改名过且从未被记录引用的预置项，按名回填匹配不到，仍可删。单人工具可接受，不在本轮解决。

**验收**：四操作三食物删除被拒且按钮禁用；改名/停用/改间隔照常；自建且未引用的项仍可删。

**测试**：erase 守护单测（预置拒绝/自建放行）、迁移回填单测。

### 票 F3：双层周期（最大一张）

**改动点**
- 迁移：`food` 加列 `suggested_interval_days INTEGER NULL`；按名回填 种子=3 / 干虾仁=7 / 面包虫=7（同 F2 边界）；预置 INSERT 带值。
- 后端：
  - `care.rs`：新增"按食物的距上次"计算——某窝某食物最近一次出现在喂食记录的日期；基线与现有规则一致取 `max(最近发生, 出眠日)`。
  - `tiles_for_colony`（care.rs:501-511）：喂食 tile 附 per-food 明细（名称/周期/距上次/超期），红态 = 操作层 `is_overdue` OR 任一食物超期。
  - `reminder.rs` `compute_due_reminders`（119-207）：新增食物层提醒条目，文案"该喂面包虫了（距上次 7 天）"；active 窝过滤天然让冬眠静音覆盖食物层。
  - `reminder_ledger`：防重维度加食物——加列 `food_id INTEGER NULL` 并调整唯一索引（迁移）；`run_check` 的 `INSERT OR IGNORE` 键同步。
- 前端：
  - `ColonyCard.vue` 喂食 tile tooltip 列各食物"距上次"天数。
  - 设置 → 食物 tab（SettingsDialog.vue）加"建议间隔"列：空 = 不限（只受统一周期管），填则 ≥1；校验复用 `validate_interval`（dict.rs:97-103）；`save_food` 扩展。

**明确不做**：统计页不加食物维度；FeedDialog 不改。

**验收**
- 连续 6 天只喂种子 → 第 7 天出现"该喂面包虫/干虾仁了"；统一周期超期仍提醒"该喂食了"。
- 未设周期的新食物不单独提醒。
- 冬眠窝两层全静音；出眠后基线从出眠日重算（食物层同规则）。
- 台账同窝同食物同日不重复；同日"操作层+食物层"同时超期时两条各记各的。

**测试**：双层超期判定、食物距上次基线（含出眠重算）、台账去重维度、tiles 明细结构、设置间隔校验。

### 票 F4：通知双通道 + Pushover

**改动点**
- `src-tauri/Cargo.toml`：新增 `ureq`（阻塞式小 HTTP 客户端，配 rustls；调度线程是普通 `std::thread`，阻塞无碍）。**注**：最初的"卸载 tauri-plugin-notification"决定已随 Q3 修订撤销，保留。
- 新模块 `src-tauri/src/pushover.rs`：
  - 启动时读 `std::env::var("PUSHOVER_USER")` / `PUSHOVER_TOKEN` 缓存；缺失即"未配置"。
  - `send(title, message)`：POST `https://api.pushover.net/1/messages.json`，超时约 10 秒。
  - HTTP 调用做成可注入（函数参数/trait），单测不真发网络请求。
- 发送路径 `reminder.rs:292-295` `send_notification`：并行双发——toast 原样保留；Pushover 结果不影响 toast。
- 台账分渠道标记（修正 Q8 讨论中"记账挪到发送后"的说法——双通道下不成立，改为**每行分渠道标记**）：
  - `reminder_ledger` 行加 `pushover_sent INTEGER NOT NULL DEFAULT 0`；当日防重照旧先插行（保证 toast 每日一条）。
  - Pushover 发送成功 → 置 1；未配置 → 跳过（不算失败、不重试）；网络失败 → 保持 0，下一轮调度补发 `pushover_sent=0` 且在 2 天窗口内的行；超窗自动作废。
- 设置通知 tab 重排（SettingsDialog.vue:410-451）：
  - 删掉"超期提醒""冬眠提醒"两个子开关（设置键留在库里、代码不再读——升级后行为统一由总开关管，原先单独关掉的类别会恢复推送，已知并接受）。
  - 总开关改名"推送通知"，语义 = 管桌面 + 手机两渠道全部提醒。
  - 保留"临近出眠提前 N 天"。
  - 新增 Pushover 状态区：显示两环境变量在进程环境中是否可读（只显示 在/不在 + 变量名，不显示值），附"修改环境变量后需重启"提示。
  - "发送测试通知"改双通道，`send_test_notification`（lib.rs:391-394）返回结构化结果，前端分渠道回显"桌面 ✓ / 手机 ✓ 或 ✗ 原因"。

**验收**
- 总开关关 → 两渠道全静音；开 → 超期（含食物层）+ 冬眠两类都双发。
- 断网：toast 照常，恢复后 ≤30 分钟内 Pushover 收到补发。
- 环境变量缺失：状态区提示"未检测到"，不重试、不刷错误。
- 测试按钮：两渠道结果分开显示。

**测试**：pushover 客户端（注入 mock）成功/失败/未配置三分支；台账分渠道标记与补发窗口；总开关过滤。

## 三、明确排除项

- 首页最近记录不加删除入口（Q6）。
- 不做"已记录 · 撤销"提示条（Q1 选了面板方案，提交前可取消即够）。
- Pushover 凭证不做设置页输入框（只读环境变量，Q4）。
- 统计页不加食物维度。
- 通知不做分类/分渠道子开关（Q7/Q9：单一总开关）。
- 冬眠段不可删除的现状维持（不在本轮范围）。

## 四、风险与边界

- Pushover 免费额度 10,000 条/月；本应用日提醒量级（个位数）远够。
- 修改环境变量后需重启应用才生效。
- "按名回填"的预置项边界：改名且从未用过的预置项不受保护/不带默认周期（F2/F3 同款，已接受）。
- 旧库升级后子开关语义作废，统一归总开关（见票 F4）。
