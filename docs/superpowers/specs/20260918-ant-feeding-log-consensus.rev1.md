## 1. 背景与目标

用户养了多窝收获蚁（大头收获蚁、针毛收获蚁，分布在家和公司两处），需要：

- 分别登记每窝的日常维护操作：喂食（种子/干虾仁/面包虫等）、活动区换水、巢穴保湿、垃圾区清理
- 记录每窝开始饲养的日期，展示饲养天数
- 对需要催促的操作（当前为喂食、垃圾清理）给出超期提醒；对水量充足的换水/保湿只登记、不催促
- 支持冬眠期管理：期间提醒静音、临近出眠与出眠日自动提醒
- Windows 上常驻任务栏托盘，随时可看；界面用 web 前端技术实现
- 数据本地存储、可导出带走

## 2. 领域模型

### 2.1 核心对象

| 概念 | 说明 |
|---|---|
| 窝（Colony） | 名字（**必填、全局唯一**，建窝/改名时校验重名）、物种、地点、开始饲养日期、状态（活跃/冬眠/已结束）。所有记录挂在窝上；同一物种可养多窝 |
| 维护操作（Care Action） | 可扩展字典，预置四种：喂食、活动区换水、巢穴保湿、垃圾清理。每种操作可配置"提醒/登记"性质与建议间隔（见 2.3）。删除规则见 2.6 |
| 食物（Food） | 可扩展字典，预置：种子、干虾仁、面包虫。删除规则见 2.6 |
| 地点（Location） | 受管理的清单（增删改，删除规则同 2.6）；预置"家/公司"两个可改项，可新增。窝的地点字段可空 |
| 记录（Log Entry） | 一次已发生的维护操作：哪窝 + 哪种操作 + 发生时间 + 备注；喂食记录可挂多种食物（一次投喂多选）。发生时间与录入时间分开存，补录合法 |
| 冬眠期（Hibernation Period） | 开始日期 + 预计结束日期 + 实际结束日期（出眠时回填）；一窝可有多段。**约束：同窝各段时间不得重叠；结束日期不得早于开始日期**（表单与数据层双重校验） |

### 2.2 数据结构（长表流水）

所有操作存统一流水表（一行一次操作），不做每操作一列的宽表——统计的本质是按时间/窝/操作类型分组聚合，长表天生适合，新增操作类型不改表结构。涉及表：窝、操作字典、食物字典、地点清单、记录流水（含喂食-食物多选关联）、间隔配置、冬眠期、提醒已发台账（见 2.7）。

**喂食构成占比口径**：按食物出现次数计数——一次多选投喂中，每种所选食物各计 1 次，各分项之和可以大于 100%；统计页环形图标注"按出现次数"。

由此直接支持的统计：任意时间段每窝每类操作次数与频率、喂食食物构成占比、每类操作实际间隔分布（平均/最短/最长，冬眠天数按 2.5 规则扣除）、日历热力图、饲养天数。

### 2.3 提醒类 vs 登记类

每个操作类型在设置里可切换二选一性质：

- **提醒类**：有建议间隔（天数），"距上次"超期在界面标红、发系统通知。当前配置：喂食（建议 3 天）、垃圾清理（建议 7 天）
- **登记类**：只记录、只显示"距上次 X 天"（中性灰），永不标红、不发通知。当前配置：活动区换水、巢穴保湿——用户用大容量水塔，水量充足，明确表示不需要被催促

### 2.4 窝状态与首页展示

- 活跃：正常展示、参与提醒
- 冬眠：卡片灰化 + 冬眠横幅，提醒静音（见 2.5），可照常记录
- 已结束：收进首页底部**"已结束"折叠区**（默认折叠，可展开查看与补录），不参与提醒；统计页与记录页仍可按窝筛选用它

### 2.5 冬眠流程与统计交互规则

流程：

1. 手动开始冬眠：填开始日期 + 预计结束日期（选定开始日期后自动预填默认结束日，可改）
2. 期间：该窝所有超期标红与通知静音；记录照常可以打（如偶尔开箱检查）
3. 预计结束前 N 天（默认 7，可配）提醒"临近出眠，开始留意动静"
4. 预计结束日当天提醒"该恢复日常照顾了"
5. 手动确认出眠：窝回到活跃状态，回填实际结束日期（可与预计不同）

统计交互规则（明确算法）：

- **冬眠期间的记录**：照常计入记录数、记录列表、日历热力图与"距上次"的天数显示
- **提醒类间隔统计**：计算相邻两次记录的间隔时，若该间隔时间段与冬眠期重叠，扣除重叠部分的天数（冬眠不算拖拖沓沓的日子）
- **"距上次"的出眠重置**：出眠确认后，提醒类操作的"距上次"基准 = max(最近一次记录日期, 出眠日期)——即出眠当天显示"距上次 0 天"起算，不会出现"出眠即全红"
- **多段冬眠**：每段独立适用上述扣除与重置规则

### 2.6 字典/清单的删除与改名规则（操作、食物、地点通用）

- **未被任何记录/窝引用**的项：可以物理删除
- **已被引用**的项：只能**停用**，不能删除。停用后不再出现在记录入口、新建/编辑表单与筛选器默认项中；历史记录与统计保留原语义（按内部 id 关联，不受影响）
- **改名**：只改显示名，内部 id 不变；历史记录与统计跟随当前显示名展示

### 2.7 提醒调度与可靠性

- **检查时机**：应用启动时立即检查一次；常驻期间由 Rust 侧定时任务**每 30 分钟**检查一次（不依赖 WebView/前端定时器，不受其节流影响）
- **触发内容**：提醒类操作超期、临近出眠（前 N 天）、出眠日
- **去重与补发**：每条提醒写入 SQLite"已发台账"（谁+哪种+哪天），同一条只发一次；系统睡眠、应用未启动等原因错过的，下次检查时按台账补发（未发过的照发，发过的不再骚扰）
- **通知默认值**：**默认开启**（与"到时间要提醒我"的核心诉求对齐）；设置里可整体关闭或分类关闭（超期提醒/冬眠提醒分开两个开关）。界面红标恒开，不受通知开关影响

### 2.8 数据与恢复

- 数据文件：SQLite 单库，存放于系统应用数据目录（设置里有"打开数据文件夹"按钮）
- **备份与恢复 = 直接拷贝 .db 文件**：拷走即备份、放回即恢复（应用关闭状态下操作）
- **导出 CSV / JSON**：定位为"数据带走/归档"（给表格软件看、留档），不是恢复通道；应用内 JSON 导入列入 v2，v1 明确不做
- **schema 版本**：库内用 `PRAGMA user_version` 记版本号；升级只走"逐版本迁移脚本"（N→N+1 顺序升），不做降级

### 2.9 其他规则

- 窝的删除：没有任何记录的窝可以直接删（建错了）；有记录的窝只能改状态为"已结束"
- 地点分组排序 = 地点在清单中的顺序（可拖动调整）；地点为空的窝归入"未分组"，排在最后
- 所有记录可编辑、可删除；时间默认"现在"可改

## 3. 技术栈

## 4. 界面结构（浅色主题）

1. **首页（卡片仪表盘）**：按地点分组（分组顺序见 2.9；空地点归"未分组"排最后），每窝一张卡：名字、物种、状态徽章、饲养天数（大数字）、**动态操作块——每个"启用中"的操作类型一块（2 列自适应网格，新增操作自动出现）**。操作块 = 一键记录按钮 + "距上次 X 天"状态：提醒类有绿（正常）/红（超期）态，登记类中性灰 + "仅登记"角标。冬眠中的窝：卡片灰化 + 冬眠横幅（入眠日期/预计出眠/剩余天数/临近出眠提醒角标），操作块静音但仍可记录。已结束的窝：首页底部折叠区（见 2.4）。卡片底部显示最近记录摘要。
2. **喂食弹窗**：点喂食块弹出：食物多选（chips）、时间（默认现在、可补录）、备注（可选）；确认后记录并刷新状态。
3. **统计页**：日历热力图（一天一格、悬停看当天明细）、喂食构成占比（环形图，按出现次数口径）、每周操作次数（柱状）、实际间隔 vs 建议间隔（仅提醒类画建议刻度，登记类标注"仅登记"；间隔已按 2.5 扣除冬眠天数）。可按窝、按时间范围筛选。
4. **记录列表页**：按窝/操作类型/时间范围筛选，备注可搜索；记录可编辑、可删除。
5. **托盘与常驻**：点窗口关闭 = 最小化到托盘（右键菜单退出）；悬停 tooltip 一句话概要；开机自启默认开（设置可关）；提醒调度与通知默认值见 2.7。
6. **设置**：操作/食物/地点清单管理（增删改/停用、提醒/登记性质、建议间隔、删除规则见 2.6）、通知开关（总/分类）、开机自启、"打开数据文件夹"、数据导出。

## 5. 明确不做（v1）

- 不记喂食数量、不存照片
- 不做多用户/账号/云同步
- 不做手机端/局域网访问
- 不做应用内 JSON/CSV 导入恢复（恢复走 .db 文件拷贝，见 2.8；导入列 v2）
- 不做每窝单独的建议间隔（全局一套）
- 不做"按日期自动进冬眠"（只手动）

### ① 查实的（11 条,每条含"改什么"——实施 spec 必须钉死的规则）

1. **备份与托盘行为冲突**(codex):"关闭状态下拷 .db" vs 点关闭=最小化到托盘。改:数据层不启用 WAL(`journal_mode=DELETE`,库文件单文件自洽);设置里提供由 Rust 执行的"安全备份"(复制库文件到指定目录);帮助写明手动拷贝需先从托盘真实退出。
2. **窝状态与冬眠段一致性**(codex):每窝至多一段开放冬眠段(实际结束日期为空);开始冬眠→状态置"冬眠";确认出眠→回填实际结束+状态回"活跃";已结束的窝不可开始冬眠;回填历史冬眠段不改当前状态。
3. **提醒台账身份**(codex):提醒身份=窝+操作类型+日期+提醒种类(超期/临近出眠/出眠日);超期提醒每个超期日最多一条;临近出眠=预计出眠日前 N 天起首次检查触发一次;出眠日=当天一次;修改预计出眠日后,未发的临近/出眠提醒按新日期重算,已发的不追回。
4. **占比口径矛盾**(codex、pi 两家独立提出):分母定为"时间范围内食物出现总次数",各分项归一化 100%(环形图成立);图例同时显示各食物出现次数;删除"总和可大于 100%"表述。
5. **停用项在编辑表单的可见性**(codex):停用项不出现在新建记录入口,但编辑旧记录时其原引用的停用项照常显示(标"已停用")且可保留。
6. **频率统计分母**(codex):频率=次数 ÷ 筛选范围自然日天数,不扣冬眠;界面标注口径。
7. **Rust 侧数据访问**(pi):数据层唯一属主为 Rust(rusqlite);前端一律经 Tauri command 读写;迁移在 Rust 启动时按 user_version 逐版本执行;不使用 tauri-plugin-sql(消除两套连接的锁问题)。
8. **补发上限**(pi):启动补发时每窝每种提醒最多补 1 条(最新);超过 7 天的过期提醒不再补发,界面红标照常显示。
9. **WAL 风险**(pi):随第 1 条一并解决——`journal_mode=DELETE`,拷 .db 即完整备份;强杀最多丢最后一个未提交事务。
10. **饲养天数口径**(pi):= 今天 − 开始饲养日期的自然日天数,含冬眠;首页与统计页一致。
11. **出眠提醒生效条件与补录刷新**(pi):临近出眠/出眠日提醒仅对状态=冬眠的窝生效,提前出眠后不再触发;任何记录增删改后界面即时重算红绿态(数据驱动,无定时延迟)。
