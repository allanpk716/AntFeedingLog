# AntFeedingLog 数据安全共识：自动备份 · 恢复 · 日志（2026-09-18）

用户提出三项需求，经两轮共 14 问评审（Q1–Q14）形成决议：

1. 数据库自动备份到指定目录（带设置与开关）
2. 应用内导入（恢复）数据库，带界面
3. 日志功能（含崩溃日志），出问题有地方查

（第四项诉求"安装包"经查已存在，无需开发。）

配套：`CONTEXT.md` 已新增"数据安全"词条（备份 / 自动备份 / 备份目录 / 备份保留 / 恢复）；`docs/adr/0002-in-app-restore.md` 记录"应用内不做导入恢复"→"整库恢复"的决策反转。

## 〇、现状盘点（评审时点事实）

- 应用：Tauri 2 + Vue 3 + SQLite，Windows 托盘常驻，单用户本地工具。库文件在系统应用数据目录（Windows: `%APPDATA%\com.antfeedinglog.app\`），journal_mode=DELETE——拷贝库文件即完整，无 -wal 伴生文件。
- 现有备份：设置页"数据"页签有**手动**"安全备份"按钮——文件对话框现选保存位置，短暂拿锁挡住并发写后拷贝库文件（`src-tauri/src/system.rs` 的 `backup_db_file`、`src-tauri/src/lib.rs` 的 `backup_to` 命令）。
- 现有导出：CSV / JSON，定位"归档带走"。库带 schema 版本迁移管线（`db.rs` 的 `open_and_migrate`，当前 v2）。
- 设置与提醒台账存于库内（settings 表、reminder_ledger）。
- 安装包已存在：打 tag 后 GitHub Actions 自动构建 NSIS setup.exe + MSI + 更新签名四件套，v0.2.0 已发布，应用内有"更新"页签。

## 一、决议总表

| # | 问题 | 决议 |
|---|------|------|
| Q1 | 安装包 | 已存在，不另开发；不做便携版 zip |
| Q2 | 自动备份触发 | 每天第一次产生新数据时备份一次；当天已备且之后无新数据则跳过 |
| Q3 | 备份目录 | 用户在设置里指定，**无默认值；未设置则自动备份不生效**（用户特别指定，否决了"默认数据目录下 backups 子目录"的备选方案） |
| Q4 | 保留策略 | 只保留最近 N 份（默认 30，可改），超出自动删最旧 |
| Q5 | 导入语义 | **整库恢复**（替换，非合并）；推翻首发"应用内不做导入恢复"决策，见 ADR-0002 |
| Q6 | 恢复保险 | 三道：恢复前自动备份当前库 → 预览摘要（几窝/几条记录/哪天的备份）→ 二次确认 |
| Q7 | 备份开关默认值 | 默认开（但目录未设置时不动作） |
| Q8 | 备份失败 | 静默记失败、下次触发自动重试；设置页显示"上次备份：成功/失败 + 时间"；不弹窗 |
| Q9 | 日志范围 | 错误（命令失败 / Rust panic / 前端异常）+ 关键动作流水（备份 / 恢复 / 更新 / 自启同步 / 提醒发送与补发）；不做全量调试日志 |
| Q10 | 崩溃提示 | 崩溃信息写日志文件；下次启动不弹窗，设置页显示"上次异常退出：时间 + 一行原因" |
| Q11 | 日志查看 | 设置页"打开日志文件夹"按钮 + 应用内显示最近错误摘要；不做诊断包 |
| Q12 | 恢复文件校验 | 只接受本应用备份：旧 schema 自动走升级管线照常恢复；比当前程序新的 schema 拒绝；损坏 / 无关 .db 拒绝 |
| Q13 | 恢复生效 | 立即生效、界面当场刷新；实现时若刷新链路过绕，可降级"提示重启生效"（届时告知用户） |
| Q14 | 恢复回滚范围 | 设置与提醒台账随库整体回滚——备份时刻的一切都回来；个别提醒可能重发一次，接受 |

## 二、配套语义（常规实现项，未逐条问用户）

- 备份文件命名沿用 `ant-feeding-log-backup-YYYYMMDD.db`；自动备份每天至多一份。
- "当天已备且无新数据跳过"的判定基准：当日是否已有成功自动备份 + 自那之后是否有新写入。
- 设置页"数据"页签扩展为三区：**自动备份区**（开关 / 目录选择 / 保留份数 / 上次备份状态）+ **现有手动三按钮**（安全备份 / 导出 CSV / 导出 JSON，行为不变）+ 新增**"从备份恢复"按钮**；**日志区**（打开日志文件夹按钮 + 最近错误摘要 + 上次异常退出显示）同页签。
- 更换备份目录不迁移旧目录中的既有备份；保留份数按当前目录独立计算。
- 恢复选文件时，文件对话框默认定位到备份目录（已设置时）。
- 恢复前的安全快照固定写在数据目录（不依赖用户是否设置了备份目录），文件名带 pre-restore 标识与时间戳。
- 日志文件落数据目录 `logs/` 子目录，纯文本，按天滚动，自动删超过 14 天的旧文件。
- 崩溃捕获：Rust panic 钩子写日志；前端未捕获异常转发 Rust 落日志。脚手架 release profile 的 `panic = "abort"` 此前已注释（恢复 unwind 语义），panic 钩子可靠。
- 动作流水首版事件清单：备份成功 / 失败、恢复执行（含来源文件）、更新检查 / 下载 / 安装结果、开机自启同步结果、提醒发出、手机推送补发 / 作废。

## 三、明确不做（Out of Scope）

- 便携版 zip 安装包
- JSON / CSV 导入（导出仍是"归档带走"）
- 合并导入（把备份记录并进当前库）
- 全量调试日志（每次 SQL / 每轮调度全记）
- 一键诊断包导出
- 崩溃弹窗通知
- 备份加密 / 压缩

## 四、实施面初步盘点（供拆票参考，非逐层实现清单）

- Rust：settings 表新增键（备份开关 / 目录 / 保留份数 / 上次备份状态）；写入路径挂钩（`log_care` 等写入后触发"当日首备"判定）；`system.rs` 增恢复（校验 / 替换 / 重载连接）；日志模块（panic 钩子、文件滚动、错误与动作流水记录）；`lib.rs` 新命令（备份设置读写、恢复、打开日志文件夹、最近错误摘要）。
- 前端：`SettingsDialog.vue` 数据页签三区改造；恢复流程（选文件 → 摘要预览 → 二次确认 → 刷新）；错误摘要展示。
- 连接管理：恢复后重建连接并广播各页刷新（程序已有 `Mutex<Connection>` 集中管理与短暂拿锁模式可沿用）。
- 测试：Rust 单测沿用"纯函数核心 + Tauri 解耦"既有模式；前端组件测试沿用现有 vitest 模式。

## 五、风险与开放点（开发期要盯）

- 恢复后"界面当场刷新"若链路过绕，降级"提示重启"（Q13 已授权降级路径）。
- 提醒台账回滚后的提醒重发窗口（Q14 已接受，留意实际体验是否可忍）。
- "当日首备"判定的并发窗口（写入高频时判定与拷贝的时序，沿用短暂拿锁模式）。
- 恢复的"新 schema 拒绝"判定依赖 schema 版本号可读（损坏文件 / 0 字节文件都要落到友好报错，不能 panic）。
