# 每窝周期(Per-colony Interval)实施规格

日期:2026-09-19 | 来源:共识 rev1(xcheck 链 20260919-220334 round0 → 20260919-221641 round1 复审收敛) | 术语:CONTEXT.md 词汇表、docs/adr/0005-per-colony-interval.md(工作区未提交稿)

## Problem Statement

不同窝的巢型不同:水塔窝看水位即可,石膏窝等需要每隔几天手动补水;同一维护操作在不同窝的必要节奏不同,而"提不提醒"与建议间隔目前挂在操作类型层全局生效,表达不了"这个窝按自己的节奏走"。用户需要一个按"窝 × 操作"设的周期:设了就按周期提醒("加水一次后按设定周期提醒下一次"),没设的窝一切照旧。

## Solution(用户视角)

在窝编辑对话框新增「周期提醒」小节:该窝每个启用的维护操作各一行、一个可选的周期输入(整数天,留空=不设)。设了周期的窝,对应操作卡片显示"距上次 N 天 / 周期 M 天",超过周期(严格大于,等于当天不算)标红"⚠ 超期 X 天",并走现有通知通道(桌面+手机推送并行)每天提醒一次、做了为止;周期从最近一次该操作记录起算,改周期立即生效。没设周期的窝与今天的行为完全一致(登记类操作依旧永不催促)。喂食设了每窝周期后不再受全局统一周期打扰,食物周期照旧叠加。冬眠静音、已结束不提醒、撤食派生、从未做过不催等既有边界全部不变。

## User Stories

1. 作为饲养者,我想给需要手动补水的窝设巢穴保湿周期,以便超期被提醒而不是靠自己记。
2. 作为饲养者,我想让水塔窝不设周期,以便它们保持安静、只显示"距上次"。
3. 作为饲养者,我想给某窝设喂食"最长 1 周"的周期,以便该窝按周节奏被提醒、不被更短的全局统一周期打扰。
4. 作为饲养者,我想设了每窝周期后食物周期仍然生效(任一层超期即提醒),以便蛋白质等食物节奏不被破坏。
5. 作为饲养者,我想在窝编辑对话框一次配好该窝全部操作的周期,以便集中管理、不进设置翻全局项。
6. 作为饲养者,我想在卡片上看到"距上次 N 天 / 周期 M 天"与超期警示,以便一眼看出哪个窝该照料。
7. 作为饲养者,我想中途设/改周期立即生效(已超期立刻标红、不宽限),以便反映当前实际。
8. 作为饲养者,我想从未做过的操作设了周期也不催,以便从第一次做了才开始算。
9. 作为饲养者,我想补录历史记录照常参与"最近一次"计算,以便周期起算点准确。
10. 作为饲养者,我想冬眠中的窝不被周期提醒打扰(打卡照常),以便冬眠期安静。
11. 作为饲养者,我想已结束的窝不产生提醒,以便历史窝无噪声。
12. 作为饲养者,我想撤食提醒保持原样,以便易腐撤食链路完全不受影响。
13. 作为饲养者,我想通知走现有桌面+手机推送通道并按天去重,以便不另学新开关、不被重复轰炸。
14. 作为饲养者,我想在网页端首页看到同样的超期标红(周期设置入口仅桌面端),以便手机上也能看到该做什么。
15. 作为饲养者,我想日后新增的自定义操作自动获得每窝周期能力,以便不必为新操作单独开发。

## Implementation Decisions

**术语**:本规格全部沿用 CONTEXT.md 词汇表——窝(Colony)、维护操作(Care Action)、每窝周期(Per-colony Interval)、建议间隔、距上次、统一周期、食物周期、待撤食、冬眠。

1. **schema v9**:新表 `colony_action_interval(colony_id INTEGER NOT NULL REFERENCES colony(id), action_id INTEGER NOT NULL REFERENCES care_action(id), interval_days INTEGER NOT NULL, PRIMARY KEY(colony_id, action_id))`,CHECK 约束 `interval_days BETWEEN 1 AND 365`。删行=未设;不预置任何行。迁移沿既有迁移链(基线 SCHEMA_VERSION=8,本链 v8→v9;规格原文写 v8 系核实基线前的笔误——v8 已被已发布链占用,复用会毁已发布库),旧库升级与全新建库两路都要。
2. **有效周期解析(钉死评审 F3 判定式)**:某窝某操作的有效周期 = 该窝每窝周期(若有)否则操作层建议间隔。喂食超期判定:`[days_since_last > 有效周期] OR [任一食物:days_since_last(该食物) > 该食物周期]`——设了每窝周期的窝**不参与**统一周期判定(操作层 OR 项二取一:每窝周期或统一周期);未设的窝照旧 `[days > 统一周期] OR [食物层]`。撤食(follow)永不参与。
3. **超期口径(钉死评审 F1)**:严格大于——`days > interval` 才标红/通知,恰好等于周期当天不提醒、次日起提醒;统一适用于每窝周期、操作层周期、食物周期三层,与既有 `is_overdue` 同构。
4. **展示口径(钉死评审 F2)**:卡片 tile 的"周期 M 天"取该窝有效周期(设了即每窝周期);"⚠ 超期 X 天"的 X = days − 有效周期,与判定同源;食物行照旧独立标各自超期;没设周期且操作为登记类的 tile 与现状逐字节一致(只显示距上次、永不红)。
5. **校验与数据生命周期(钉死评审 F4)**:周期输入校验整数 1..365,非法拒绝并给人话报错;删除自定义操作的引用守卫在既有 care_log/reminder_ledger 计数之外补 colony_action_interval 计数(有引用即拒删、提示可先清周期,文案风格同既有);删除窝的事务顺带清理该窝全部周期行。外键沿库内惯例裸 REFERENCES、应用层守卫,不引入 ON DELETE CASCADE。
6. **API 契约**:读侧——窝列表/首页 tiles 数据在现有结构上携带每窝周期(每窝每操作的有效周期与"是否来自每窝周期"足以支撑展示;原始操作层间隔字段保留不动);写侧——新增桌面命令设置/清除某窝某操作的周期(入参:colony_id、action_id、interval_days 或清除),注册进桌面命令表;**不得**加入网页端 HTTP 命令白名单(网页端无管理入口),但读侧数据对网页端可见(首页超期红同源生效)。
7. **提醒引擎**:按日计算与通知台账(每日去重、做了为止)机制不变;逾期判定换用有效周期;通知文案中的周期值取该窝有效周期;冬眠静音、已结束过滤、从未做过(days 为空)不产生提醒等既有过滤全部照旧。设/改/清周期不需要主动触发通知,下一轮调度自然生效(卡片即时刷新即可)。
8. **前端**:类型与纯逻辑层同步新字段;窝编辑对话框加「周期提醒」小节(启用的操作各一行:操作名 + 可选周期输入 + 清除;撤食不出现);卡片按第 4 条展示;入口仅桌面端(窝编辑本就属管理功能)。
9. **统计(共识 D10 最小口径)**:统计页不改口径,StatsInterval 继续按操作层建议间隔列示,不纳入每窝周期。

## Testing Decisions

只测外部行为,不测实现细节;沿用仓库既有先例(Rust 侧 cargo test 内嵌于模块文件,前端 vitest + 组件测试 mock IPC 模式)。

- **schema/迁移**:v7 库升级到 v8 出现空周期表、新库直建含表、重复迁移幂等(先例:迁移链测试)。
- **有效周期与判定**:设/未设/喂食取代统一周期/食物层照旧叠加/严格大于边界(days==interval 不红、==interval+1 红)/撤食不受影响(先例:care.rs 判定测试)。
- **提醒引擎**:超期按有效周期每日一催、做了为止;每窝周期取代统一周期后不再被全局短间隔触发;冬眠静音;已结束不催;从未做过不催;台账按天去重(先例:reminder.rs 现有测试族)。
- **命令与校验**:设/清周期往返;0、负数、366、非整数拒绝;删自定义操作有周期行引用时拒删;删窝后周期行清理。
- **前端**:tile 文案三种形态(设周期未超/超期/未设);窝编辑小节设、清、校验与撤食不出现;未设周期窝的卡片渲染与现状一致(先例:care.test.ts、组件测试)。

## Out of Scope

- 小时粒度周期(撤食间隔小时制不动)。
- "每窝 × 每食物"维度(食物周期仍全局按食物)。
- 待撤食派生逻辑与撤食间隔。
- 网页端管理入口(含周期设置)。
- 预置/迁移猜任何窝的初始周期。
- 全局"提醒类/登记类"性质与操作层/食物层间隔既有语义的任何变更。
- 统计页口径变更(见 Implementation Decisions 第 9 条)。
- CONTEXT.md 与 docs/adr/0005-per-colony-interval.md 文档本身(已在用户工作区,由用户决定提交,本链不触碰)。
