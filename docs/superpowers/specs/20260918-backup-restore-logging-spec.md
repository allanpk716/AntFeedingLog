# 数据安全二期实施 Spec：自动备份 · 恢复 · 日志（2026-09-18 夜链）

来源：共识文档 `20260918-backup-restore-logging-consensus.md` → rev1（含两轮交叉评审附录）。本 spec 把 rev1 机制细则与评审查实的 12 条钉死项合并为最终实施口径；术语遵守 `CONTEXT.md`（备份/自动备份/备份目录/备份保留/恢复）与 `docs/adr/0002-in-app-restore.md`。

## Problem Statement

用户的三项诉求：(1) 数据库能自动备份到指定目录，有设置和开关；(2) 能在应用内导入（恢复）数据库，有界面；(3) 有日志功能，出问题（含崩溃）有地方查。现状：只有手动"安全备份"（每次现选位置），恢复只能手工拷文件，无日志。

## Solution（用户视角）

- 设置页"数据"页签新增**自动备份区**：开关（默认开）、备份目录选择、保留份数（默认 30）、上次备份状态（成功/失败+时间）；未设目录时显示"未设置备份目录，自动备份未生效"。
- 自动备份**每天至多一次**：当天第一次产生新数据时备份；之前失败过则下次启动或下次写入自动补；备份目录写不进去时静默记失败、不弹窗。
- 新增**"从备份恢复"**按钮：选备份文件 → 预览（几窝/几条/哪天的备份）→ 二次确认 → 整库替换、立即生效（或明确提示重启）。
- 设置页新增**日志区**：打开日志文件夹、最近错误摘要、"上次异常退出：时间+原因"。
- 手动"安全备份 / 导出 CSV / 导出 JSON"三按钮保持现状。

## User Stories

1. 作为饲养人，我想让应用在每天第一次产生新数据时自动把数据库备份到我指定的目录，以便电脑坏了数据也不丢。
2. 作为饲养人，我想在设置里开关自动备份并指定备份目录，以便把备份放进网盘同步目录等任意位置。
3. 作为饲养人，我想在"开关开着但目录没设"时看到"未生效"提示，以便不会误以为备份在跑。
4. 作为饲养人，我想备份目录只保留最近 N 份（默认 30），且应用**绝不删除**不匹配自动备份命名模式的其他文件，以便既不占空间又不误删。
5. 作为饲养人，我想备份失败（网盘掉线/U 盘拔出）时不被弹窗打扰，并能在设置页看到失败与时间，以便知情不烦。
6. 作为饲养人，我想昨天备份失败后应用在下次启动时自动补一次，以便失败不会永远漏掉。
7. 作为饲养人，我想恢复前看到备份摘要（窝数/记录数/备份日期/备份内的备份目录设置值），以便确认没选错文件。
8. 作为饲养人，我想恢复前应用自动把当前数据先备一份（反悔通道），以便恢复错了有救。
9. 作为饲养人，我想恢复立即生效；若做不到，得到明确的"请重启应用"提示，以便不困惑。
10. 作为饲养人，我想选错文件（非本应用备份/损坏/未来版本/正被使用的当前库本身）时得到明确拒绝信息，以便不会恢复出乱数据。
11. 作为饲养人，我想在设置页一键打开日志文件夹并看到最近错误摘要，以便出问题能自查或求助。
12. 作为饲养人，我想程序异常退出后，下次在设置页看到"上次异常退出：时间+原因（无崩溃日志时标注'疑强杀/断电'）"，以便知道发生过什么。
13. 作为饲养人，我想日志自动清理 14 天前的旧文件，以便不无限占空间。
14. 作为饲养人，我想保留手动"安全备份"现状，以便临时拷一份到 U 盘。

## Implementation Decisions

### D1 · 备份元数据出库（评审附录 #3 的修复方案，属 Q14 的知情细化）

备份管理的全部元数据——开关、备份目录、保留份数、`last_backup_date`（最后成功备份日期）、`last_data_write_date`（最后业务写入日期）、上次备份结果与时间——存**库外独立文件** `backup-config.json`（数据目录），不进 SQLite settings 表。

- 效果一：恢复整库**不会**回滚备份设置与备份账目 → 恢复点之后新产生的备份不会被回滚出的旧保留数删除（附录 #3 的删除风险根除）。
- 效果二：元数据写入不触库 → round 0 查实的"备份状态写库自触发"回路从结构上不存在。
- Q14 语义细化：其余设置与提醒台账仍随恢复整体回滚（用户已确认）；备份元数据是运维层账目，不随回滚。恢复确认弹窗写明"备份设置保持当前值，不随恢复回滚"。**此细化需用户过目**（记入晨报）。

### D2 · 自动备份触发（附录 #1/#5 的修复）

统一谓词：**需要备份 ⇔ `last_data_write_date > last_backup_date`**（存在比最后成功备份更新的业务数据），叠加 `开关开 ∧ 目录已设`。

- 触发点两处，共用该谓词：①每次业务写入完成后（记录/窝/字典/冬眠的增删改；元数据写库与备份配置写文件都不算）；②应用启动时。
- 语义自然覆盖：当日首写即备、当日后续写入不重备（`last_backup_date` 已追平）、失败后当日后续写入与**次日启动**都会补跑（谓词仍成立）、跨日首启无新数据不备（谓词不成立）——修复"每日首启空备份"。
- 时钟回拨钳制（附录 #5）：任一日期键晚于今日 → 视为无效（`last_backup_date` 清为空、`last_data_write_date` 钳到今日），备份不停摆。

### D3 · 备份执行协议

1. 短暂拿库锁 → 库文件拷到数据目录临时文件（本地毫秒级）→ 释放锁。
2. 锁外把临时文件拷到备份目录（网络盘/慢速盘不占库锁、不阻塞记录与 UI）。
3. 成功：删临时文件、更新 `backup-config.json`；失败：静默记失败（原因+时间）、清理临时文件、待下个触发点重试。
4. 自动备份命名 `ant-feeding-log-backup-YYYYMMDD-HHMMSS.db`（含时分秒，杜绝同日同名覆盖）。

### D4 · 保留淘汰（附录 #2/#7 的修复）

只清理备份目录内**匹配 `ant-feeding-log-backup-<8位日期>-<6位时间>.db` 且时间戳可解析**的文件；按**文件名内时间戳**（非 mtime）排序，超出保留份数删最旧。其他文件（手动备份、无关 .db、文档）绝不触碰。

### D5 · 恢复协议（四步 + 失败语义 + 摘要预览）

1. **源校验与 staging**：拒绝"源路径 == 当前库路径"；把源文件复制为数据目录 `restore-staging-<时间戳>.db`，此后一切在临时库上进行，不碰当前库。
2. **临时库校验**：可打开（否则"这不是本应用的备份"）→ `PRAGMA integrity_check` 为 ok（否则"备份文件已损坏"）→ schema 版本：旧版在临时库上跑迁移管线升级后复校；比当前程序新则拒绝（"请先升级应用"）。校验通过即产出**摘要**：备份日期、窝数、记录数、库内（旧）备份目录设置值。
3. **pre-restore 快照**：当前库拷 `pre-restore-<时间戳>.db` 至数据目录，**最多保留 3 份**，超出删最旧（同样只匹配自家命名模式）。
4. **替换与重载**：拿库锁 → 锁内以"写新文件+原子改名"方式替换（`Mutex<Connection>` 下 `*guard = 新连接` 的标准替换；旧连接 drop 受锁保护）→ 重建连接 → 广播各页刷新；刷新链路过绕则降级为"提示重启生效"。**重建失败恢复路径**（附录 #10）：重试 3 次（短退避）→ 仍失败则保持新库文件、提示"恢复已完成，请重启应用"。
- **失败语义**：步骤 1–3 任一失败 → 当前库零改动、清理 staging、报具体原因；步骤 4 是唯一写动作且先写后改名，中途失败原库文件未破坏——"自动回滚"由协议结构保证。
- 恢复后：提醒台账/其余设置随库回滚（Q14），备份元数据不动（D1）；确认弹窗文案点明两者。

### D6 · 来源校验（provenance，附录 #6 的处置）

v1 不做 manifest/应用标识；校验集 = 可打开 + integrity_check + schema 版本（v2 仅本应用产生）。**摘要预览是用户最后防线**——测试必须覆盖"选错文件时摘要能暴露"。未来可加 manifest，记 Further Notes。

### D7 · 日志模块

- 落数据目录 `logs/`，纯文本，按天滚动，自动删 >14 天文件。
- 记录：错误（命令失败/Rust panic/前端未捕获异常转发）+ 动作流水（备份成功/失败、恢复执行含来源、更新检查/下载/安装结果、自启同步、提醒发出、推送补发/作废、启动与正常退出）。
- panic 钩子可靠的前提（release 已回 unwind）保持；脚手架不得再引入 `panic=abort`。

### D8 · 异常退出判定（附录 #4 的修复：退出路径全枚举）

- 运行标记：启动时写（含启动时间），**清理接入全部可识别的优雅退出路径**：托盘"退出"、应用内更新安装的重启前、主事件循环正常收尾（RunEvent::Exit，覆盖 OS 关机/注销时的正常销毁序列）。
- 残余误报（清理失败的非常规退出）如实显示；原生崩溃/强杀/断电无日志可写——运行标记仍能识别为"异常退出"，无原因行时显示"（无崩溃日志，疑强杀/断电）"。

### D9 · 单实例（附录 #9）

接入 Tauri 单实例插件：第二实例启动时聚焦已有主窗口并退出。运行标记、备份账目、库单写者都以单实例为前提。

### D10 · 命令契约（Tauri commands，前端仅经此访问）

- `get_backup_config` / `set_backup_config`（开关/目录/保留份数；目录经系统文件夹选择框选取）
- `get_backup_status` → {上次结果, 上次时间, last_backup_date, last_data_write_date}
- `backup_to`（手动安全备份，现状不变）
- `restore_preview(path)` → 摘要 {备份日期, 窝数, 记录数, 备份内目录设置值} | 拒绝原因
- `restore_apply(path)`（重走校验后执行四步协议；TOCTOU 安全）
- `open_logs_folder` / `get_recent_errors` / `get_last_abnormal_exit`

### D11 · UI（设置页"数据"页签三区）

自动备份区（D2/D3/D4 语义）+ 现有手动三按钮（不动）+ "从备份恢复"按钮（走 D5 流程：选文件 → 摘要 → 二次确认 → 刷新/重启提示）；日志区（D7/D8 展示）同页签。帮助文案同步新语义，清除"应用内不做导入恢复"旧口径（ADR-0002 后续动作）。

## Testing Decisions（只测外部行为；沿用"纯函数核心 + Tauri 解耦"既有模式与 vitest 组件测试先例）

- 触发谓词纯核心：当日首写触发/同日不重备/失败重试（写入点与启动点）/跨日空启动不备/时钟回拨钳制/目录未设不触发。
- 保留淘汰纯核心：只匹配自家命名模式（同目录放手动备份与无关 .db 断言不删）/按文件名时间戳排序/超 N 删最旧。
- 备份执行：锁内临时→锁外拷目标的两段式（临时文件清理断言）/命名含时分秒。
- 恢复纯核心：staging 校验链（好库/坏库/integrity 失败/旧 schema 升级/未来版本拒绝/源=当前库拒绝）/摘要内容/快照保留 3 份/替换后可打开且数据完整/失败路径当前库零改动。
- 异常退出：标记写/各退出路径清理/残留判定；单实例第二实例聚焦。
- 组件测试：未设目录提示文案/恢复流程（摘要→确认→结果）/错误摘要展示。
- 附录无定论项转入 Further Notes 开发期盯。

## Out of Scope

便携版 zip；JSON/CSV 导入；合并导入；全量调试日志；诊断包导出；崩溃弹窗通知；备份加密/压缩；备份 manifest（D6，未来）；硬崩溃的崩溃日志（物理不可得，运行标记兜底）；异步备份框架（锁外拷贝已消除阻塞，无需）。
