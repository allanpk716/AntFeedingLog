# 实施规格 · 局域网网页端 + 巢况登记 + 数据包备份（2026-09-19）

来源:`docs/superpowers/specs/20260919-webui-checkin-consensus.rev1.md`(含两轮评审附录,37 条查实缺口已全数并入本规格)。术语遵守 `CONTEXT.md` 词汇表;决策背景 `docs/adr/0003`(网页端双闸)、`docs/adr/0004`(数据包备份)。

## Problem Statement

饲养记录目前只能在主电脑解锁桌面后记录;Pushover 推送凭据只能改系统环境变量;没有蚁群规模(蚁后数/工蚁数)与蚁巢照片的历史;备份只保 SQLite 库文件,照片进来后无处安放。用户需要:手机在受信虚拟网段(NetBird)内随时记录,不输密码;阶段性登记蚁口与巢况照片;备份恢复覆盖照片且兼容旧备份文件。

## Solution(用户视角)

同一个程序照旧常驻托盘;启用"网页端"后,从本机网段列表勾选受信网段(NetBird 段自动识别置顶),复制带进门凭证的完整地址存成手机书签,手机打开即用。网页端能打卡、翻历史、做冬眠操作、登记巢况(数蚁口+拍照+备注);管理类操作仍在桌面端。Pushover 在设置页可配(不填回落环境变量)。备份自动带上照片;旧的单库备份文件仍可恢复。任一端记录,另一端开着就自动刷新。

## User Stories

1. 作为饲养者,首次启用网页端时,我想从本机网段列表勾选受信网段(NetBird 段自动识别并置顶标名,虚拟化噪音网卡不出现),以便只有我的虚拟网能访问。
2. 作为饲养者,启用向导/设置页里,我想复制完整的访问地址(含凭证)存成手机书签,以便打开即用、永远不输密码。
3. 作为饲养者,凭证可能泄露时,我想在设置页一键重生成并拿到新地址,以便旧凭证立即全部作废。
4. 作为饲养者,我想在手机首页看到各窝卡片与超期标红,并直接打卡(补录/选食物/备注),行为与桌面端一致。
5. 作为饲养者,我想在手机上翻查历史记录、修改一条、删除一条(两段确认照旧)。
6. 作为饲养者,我想在手机上开始冬眠、出眠、补录冬眠期。
7. 作为饲养者,我想给一窝登记巢况:日期、蚁后数、工蚁数(都可空)、若干照片(可零张)、备注、换巢标记;至少一项非空才可提交。
8. 作为饲养者,我想修改/删除一条巢况登记(删除带两段确认,照片文件一并删除);入巢第一条即基线,基线=最早一条登记的日期字段,可改,删首条后下一条最早者自然接任。
9. 作为饲养者,我想在手机上拍照上传、在桌面上选文件上传巢况照片;照片自动压缩(长边 2048、JPEG 质量约 85),原图不留,GPS 等元数据全部清除。
10. 作为饲养者,我想在窝卡片看到最新蚁口与"距上次登记"天数,在窝详情看到巢况时间线(含照片)。
11. 作为饲养者,我想删除一窝时(既有两段确认)该窝全部巢况与照片一并清理;归档窝则全部保留。
12. 作为饲养者,一端记录后,另一端开着的页面自动刷新;手机锁屏/断网回来也不停留在旧数据。
13. 作为饲养者,我想在设置页配置 Pushover 用户键与应用令牌(打码可看、可测试),应用内没填时自动用系统环境变量,并标明当前生效来源。
14. 作为饲养者,我想备份(手动/自动)产出单一数据包文件,内含库与全部有效照片;恢复时看到摘要(几窝/几条/照片几张),失败时现状分毫不损。
15. 作为饲养者,我想旧的纯库备份文件照样能恢复(恢复后照片场景按孤儿治理);恢复完所有端无条件刷新。
16. 作为饲养者,我想改端口/网段后防火墙规则自动重建,关闭网页端后端口不再监听、规则删除。
17. 作为老用户,升级新版后旧数据原样,升级前的备份仍可恢复、可回退。

## Implementation Decisions

### A. 进程与传输层
- 同一 Tauri 进程内嵌 HTTP 服务(端口默认 17321,设置页可改 1024–65535;被占用则不启动并在设置页/托盘提示);设置页开关,默认关;首次启用向导(选网段→生成凭证→展示完整地址→UAC 加防火墙规则)。
- **统一调用层**:前端引入单一传输适配模块,桌面走 Tauri IPC、浏览器走 HTTP;约 55 处组件直调机械改造;不引入第二套界面;首页与打卡面板做手机竖屏适配。
- **API 白名单,默认拒绝(deny-by-default)**:HTTP 层只暴露显式登记端点:首页数据、打卡(字典读+提交)、历史(查/改/删)、冬眠操作、巢况登记(查/改/删+照片上传+照片读取)、SSE、sse-ticket、健康检查、数据版本;未登记路径一律 404。桌面 53 命令不受影响。
- **服务端输入校验**:白名单≠校验——所有端点对 ID(正整数)、日期(格式+范围)、分页(上限)、枚举、字符串长度、数值范围做服务端校验,不依赖前端 UI 约束。

### B. 双闸安全
- **闸一·网段白名单**:全网卡监听,只放行所选网段来源;判定只认 socket 对端地址,忽略一切转发头;IPv4 CIDR 匹配,IPv6 默认拒绝;网段多选;枚举过滤虚拟化噪音网卡。
- **虚拟网段识别按接口身份**(接口名 wt0/NetBird 提供方),不按 CGNAT 段一刀切;无法确认身份的 100.64–127 地址**仍走物理网段硬警示**(CGNAT≠加密隧道)。
- **物理网段硬警示**:勾选任何非"已确认加密身份"的网段时,强制确认框明示"该网段内凭证与数据明文传输";不确认不给勾。
- **请求限制**:普通请求体 ≤1MB、照片上传 ≤15MB/张、普通并发上限 8、**SSE 长连接单独计量(上限 4,不挤占普通请求)**、读超时 30 秒、header 数与单条长度上限。
- **闸二·访问凭证**:
  - 首次启用生成 ≥128bit 随机凭证;**设置页不提供"自定义凭证"输入,只提供查看/重生成**(杜绝弱凭证);重生成即旧凭证全量失效。
  - 完整地址形如 `http://<IP>:<端口>/#token=<凭证>`(fragment 不随请求发给服务器);页面加载后凭证存 localStorage 并 `replaceState` 清净地址。定位是"降低暴露",**不承诺清除浏览器历史/书签/同步**——设置页明示提示:勿转发地址、可重生成作废。
  - API 请求以 `Authorization: Bearer <凭证>` 头携带;照片/SSE 资源同源自动带。
  - **SSE 短时票据**:`POST /api/sse-ticket`(主凭证换 60 秒一次性票据,仅约束建连);**客户端关闭 EventSource 原生自动重连**(onerror 中 close),error 后重新申请票据再建连;票据一次性(建连即消费)。
  - 凭证存数据目录独立 JSON(不进库),整库恢复不回滚;备份/恢复不触碰该文件。
- **防火墙联动**:固定规则名、入站、限定"所选网段+当前端口";改网段/改端口→删旧建新;关闭网页端→删规则;失败落错误流水+设置页附现成手动命令。

### C. 数据版本与实时刷新
- 每次写操作提交后广播数据版本号;桌面走 Tauri 事件、网页走 SSE。
- **版本号单调性(跨重启/跨恢复)**:库内 meta 表存计数器,每次写事务内 +1;实例启动 epoch(安装 id+启动时间)附在 SSE 首帧——**客户端比对"同 epoch 且版本落后"才判旧;epoch 不同一律整体重拉**;恢复完成事件令所有端无条件刷新。
- SSE 连接建立/重连首帧推当前版本号;客户端落后即重拉当前页。

### D. Schema v7(只加不改)
- 迁移链追加 v6→v7,单一事务;旧表结构零改动。
- 新表:`nest_checkin`(id、colony_id 外键、日期、蚁后数可空、工蚁数可空、换巢标记、备注、创建时间);`nest_photo`(id、checkin_id 外键、**相对路径** photos/ 下 `<colonyId>/<uuid>.jpg`、原始文件名仅备注、备注);`data_meta`(键值:数据版本计数器等);设置表新增 Pushover 键(键值表无需结构变更)。

### E. 照片管线
- **写入协议**:ensure `photos/<colonyId>/` 目录 → 写 `photos/<colonyId>/.tmp-<uuid>`(fsync)→ 同目录原子 rename 为 `<uuid>.jpg` → 库事务插元数据并提交;任一步失败:已 rename 未插库→删文件再报错;自动备份"当日新数据"以**元数据提交成功**为准。
- **上传校验链**(桌面/网页同一套):单张压缩前 ≤15MB;单次 ≤9 张;格式白名单 JPEG/PNG/WebP;**解码前先校验头部宽高/总像素上限**(拒绝超限,防解码炸弹);仅接受静态图;完整解码后**重编码输出**(统一 JPEG、长边 2048、质量≈85)——重编码即清除全部 EXIF(含 GPS);照片响应 `image/jpeg`+`nosniff`+`inline`。
- **落盘文件名一律服务端 UUID**;客户端文件名只进备注,不参与路径。
- **删除顺序**:先库事务删元数据并提交 → 再删文件;文件删除失败仅产生孤儿(下轮巡检隔离),不回滚库。
- **孤儿治理**:库无引用的照片文件于启动/恢复巡检时移入 `photos/.orphan-<时间戳>/`(移动非删除);设置页提供"查看并清理孤儿照片"。
- **缺图展示**:库引用的照片文件缺失(恢复裸库遗留等)时显示占位符+提示,不报错不崩溃。

### F. 数据包备份与恢复
- **格式**:zip;根 `manifest.json`(格式版本、创建应用版本、时间、库文件名+SHA256、照片清单[相对路径+SHA256]、总数与总字节)+库+照片(按相对路径)。
- **打包**:锁内拷库;**清单驱动**——只收库内引用的照片;打包前校验每张引用照片存在且可读;**读取时文件缺失→跳过该张+错误流水告警**(不整包失败);跳过 `.tmp-`/`.orphan-`。
- **恢复(数据包)**:读 manifest → 格式版本检查(未来拒) → 逐文件 SHA256 校验 → **磁盘空间预检按 zip 实际条目元数据**(峰值留 1.2×) → 解包到暂存目录(**严格路径 grammar:仅允许 `[A-Za-z0-9_-]+/[A-Za-z0-9_-]+\.jpg` 形态的清单内路径;拒绝反斜杠/冒号/绝对路径/`..`/符号链接/重复条目/清单外文件**) → 库走既有 staging 校验链(integrity+迁移) → **校验包照片集合覆盖库内引用(缺失即拒绝恢复)** → pre-restore 快照(数据包形态) → 锁内替换库 → 照片从暂存目录逐文件 rename 落位 → 清退 photos/ 中非清单文件 → 广播无条件刷新。
- **失败语义(不变量:任何一步失败,当前库与 photos/ 均未被破坏)**:替换库之前一切在暂存区;库替换后到照片落位之间失败——新库已引用的照片**必然已在暂存区就绪**,重试/重启后继续落位(恢复可续);清退放最后,残留即孤儿由巡检收。
- **恢复(旧裸库)**:照既有 staging 迁移链;photos/ 不动;恢复后现存文件按孤儿治理。
- pre-restore 快照升级为数据包(保留 3 份照旧);导出 CSV/JSON 补巢况数据。

### G. Pushover 配置
- 优先级:应用内 > 环境变量 > 未启用;设置页标生效来源;打码可看明文;测试按钮照旧;存 settings 键(随库走)。明文入库并随备份扩散的风险已明示接受(DPAPI 与数据包可携冲突,弃)。

### H. 网页端功能面
有:首页/打卡/历史(改删)/冬眠操作/巢况登记(含上传);无:统计、窝管理、字典、备份恢复导出、更新、设置——全部桌面专属。

## Testing Decisions

- 只测外部行为,不测实现细节;沿用仓库先例:Rust 纯核注入 `&Connection`/时钟/传输 + tempfile;前端统一调用层 mock(替代现状逐组件 vi.mock invoke)。
- Rust 新增(外部行为级):写入协议失败注入(rename 后插库失败→文件被清;插库失败不触发自动备份);删除顺序(先库后文件,文件失败=孤儿);打包缺文件降级(跳过+流水);恢复协议中断注入(暂存/替换/落位/清退各断点,现状不破坏、可续);manifest 校验(哈希错/版本未来/照片集合缺→拒);路径 grammar 表驱动拒绝表;版本号跨"重启"(新连接)与恢复后单调/无条件刷新;票据一次性与过期;白名单 404;输入校验边界。
- 前端新增:调用层双模式路由;凭证 fragment 提取与 localStorage;SSE 重连(关原生重连+重取票据+版本对账);巢况登记表单(全空拒绝);手机布局快照。
- **真机冒烟清单(进晨报,人工做)**:手机实连打卡与拍照上传;UAC 弹窗与防火墙规则核对;托盘常驻/关窗行为;锁屏回来刷新;拔掉 NetBird 后端口不可达。

## Out of Scope

HTTPS、密码登录、多设备部署、网页端设置/管理操作、统计图表手机版(后置)、原图保留、照片修图、DPAPI、IPv6、工蚁数趋势折线(后置)。
