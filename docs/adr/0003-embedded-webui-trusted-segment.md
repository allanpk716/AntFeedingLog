# 进程内嵌网页端，受信网段+令牌双闸（反转 ADR-0001"无需局域网访问"的前提）

ADR-0001 选 Tauri 2 时"已确认不需要手机/局域网访问"，2026-09-19 需求反转：用户要在受信虚拟网段（NetBird，接口 wt0，100.x 段）内用手机浏览器记录，不开电脑屏幕、不输密码。决定在同一 Tauri 进程内嵌 HTTP 服务提供网页端：**全网卡监听 + 受信网段白名单 + 访问令牌**双闸；网页端只做记录类功能（首页、打卡、历史记录、冬眠操作），管理功能留桌面端；任一端写入后广播数据版本号，另一端实时刷新（网页端走 SSE，桌面端走事件）；令牌存数据目录独立 JSON 文件，整库恢复不回滚它（沿 backup-config.json 的先例，否则手机书签会因恢复旧库而集体失效）。

## Considered Options

- 绑定所选网卡的单一 IP：口子最小，但开机自启时 NetBird 常晚于本程序就绪，绑定即失败；虚拟网 IP 变更也失效——弃，改全监听+白名单，由令牌兜底。
- 纯零鉴权（连令牌都不要）：暴露面 = 整个受信网段内任意进程；用户选择加令牌，把暴露面缩到持有完整网址的设备——弃。
- 独立服务进程 / 部署到 NUC 等常驻机：需求实为"本机常开 + 手机随手记"，单进程内嵌已覆盖，多一个部署物反而多一个故障点——弃。
- 网页端全功能对等：备份/恢复/更新等 7 个命令（文件对话框、打开文件夹、落盘导出）在浏览器里无意义或结果落在服务器侧——弃，按"记录、不管理"裁剪。

## Consequences

- ADR-0001 的选型结论（Tauri 2 壳）维持，但其"无需局域网访问"前提作废。
- 前端现状是约 55 处直调 Tauri IPC、无传输抽象；需引入统一调用层做"桌面 IPC / 浏览器 HTTP"双模式，属一次性机械改造。
- 防火墙需一条"仅受信网段 + 端口"的放行规则，首次启用网页端时以一次 UAC 授权自动添加。
