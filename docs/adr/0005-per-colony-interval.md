# 提醒粒度下沉到窝层：每窝周期覆盖操作层性质与间隔

「提醒类/登记类」原本是操作类型层的全局性质：巢穴保湿、活动区换水因"水塔窝看水位就行"被设为登记类（永不催促），喂食/垃圾清理走操作层建议间隔。实际饲养中各窝巢型不同（水塔窝无需周期，石膏窝要按几天一次的节奏补水），且一切可登记的维护操作本质上都是周期性的——同一操作在不同窝的必要节奏不同，操作层一个间隔表达不了。决定：新增**每窝周期**（挂在"窝 × 操作"上的天数）：设了即提醒（超期标红、每日通知、做了为止）并**取代该操作层的建议间隔**——喂食即取代统一周期，食物周期照旧叠加（任一超期即提醒）；没设的窝沿用操作层性质与间隔，登记类对它们依旧永不催促。机制对全部操作通用（含日后新增的自定义操作），入口在窝编辑对话框（桌面端，网页端不加管理入口）；撤食不适用（性质固定跟随喂食）；冬眠静音照吃（不加入待撤食式的豁免）；从未做过该操作的窝不提醒、第一次做了才开始算；设周期时已超期的立即标红、不宽限。

## Considered Options

- **全局翻提醒类 + 水塔窝逐窝静音**：让不想被催的窝默认挨催再逐窝去关，opt-in 方向反了，与"用户明确不想被催"的既有共识相反。
- **三层并列、任一超期即提醒**：全局间隔短于每窝周期时（如全局 4 天 vs 每窝"最长 1 周"），每窝周期形同虚设，表达不了"这个窝按自己的节奏走"。
- **每窝周期连食物周期一起取代**：会废掉已配好的食物节奏（蛋白质周期等），无此诉求。
- **只给巢穴保湿做专用机制**：所有登记操作本质上都周期性，迟早要泛化到换水/喂食等，专用即返工。
- **把登记类改成"间隔设得很长的提醒类"**：CONTEXT.md 早已明确拒绝——用户不想被催的窝就该真正安静。

## Consequences

- 库迁移 schema v8：新增"窝 × 操作"周期表（colony_id + action_id + 天数，可空）。
- 提醒引擎、卡片、托盘的"有效周期"改为按窝解析：先查每窝周期，没有再落操作层——`is_overdue` 的判定从"操作层性质 + 间隔"变为"每窝周期（如有）优先"。
- 水塔窝行为零变化：不设周期即今天的行为（打卡、显示"距上次"、永不标红、永不通知）。
- CONTEXT.md 已同步：新增「每窝周期」词条，「提醒类/登记类」「建议间隔」「统一周期」「食物周期」随改。
