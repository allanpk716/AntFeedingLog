# 喂食提醒按大类计时：大类周期取代逐食物周期

ADR 0007 钉死"大类不参与提醒"，喂食提醒按每种食物各自的建议间隔计时。实践发现蛋白质是轮换喂的（面包虫干、虾干、樱桃蟑螂互换）：每种蛋白质各有一只钟，喂了虾干不会重置面包虫干的钟，同一天被重复催办"该喂两个东西"。决定把提醒粒度从食物上移到大类：建议间隔挂在大类上（大类周期），喂大类内任一食物即刷新整类的钟，超期只提醒一条"该喂蛋白质了"；食物不再有各自的建议间隔。本 ADR 推翻 0007 的"大类不参与提醒"，大类的其余约定（固定三种、CHECK 锁死、key 落库）不变。

## Considered Options

- **同大类互相刷新（保留每食物间隔）**：被否。喂任一同类食物把大类内所有钟一起归零，实际上是对大类钟的模仿；保留每食物间隔这个自由度后，同大类间隔不一致时行为无法解释——虾干 3 天超了、自建蟋蟀 5 天没超，提醒文案无话可说。
- **维持逐食物周期**：被否。轮换喂养下必然重复催办，正是本次要修的问题。

## Consequences

- 大类周期在设置·食物区按大类配置（种子 / 蛋白质 / 糖水各一个天数，可清空＝该大类不按周期提醒）；预置默认沿 v13 改值：种子 7、蛋白质 3、糖水 3。
- v13→v14 迁移：food 的建议间隔列废弃；大类周期初值 = 该大类内所有食物现间隔的最大值（宽松优先——升级后绝不新增提醒，只可能变松）。
- 提醒台账身份的 food 维度换为大类；通知与卡片文案按大类名（"已 N 天没喂蛋白质（建议 3 天一次）"）；与统一周期（或被每窝周期取代后的有效周期）任一超期即提醒、互不取代——沿食物层与操作层叠加的既有语义。
- 逐食物"距上次"降级为喂食块悬停参考；"某个具体蛋白质很久没喂"不再提示（轮喂多样性由饲养人自行掌握，已确认接受）。
- 从未喂过某大类、或该大类内全部食物停用 → 该大类不提醒（沿"从未记录不催"口径）。撤食（易腐按小时）不受影响，仍是逐食物口径，与按天的大类周期两套体系。
- 统计页间隔条形图只含操作层（喂食/清理等），从不按食物画——无需改动。
