# 网页端开放「点击升级」入口，部分反转 ADR-0003 的更新裁剪

ADR-0003 当年以"更新等命令在浏览器里无意义或结果落在服务器侧"把更新裁给桌面端；2026-09-30 用户反转这一条：升级结果落在服务器侧正是要的行为——手机上点确认，电脑上的程序下载并自动重启，升级对象就是同进程内嵌服务本体。决定向网页端白名单放行两个命令（只读红点详情 + 触发既有升级确认流）；令牌 + 受信网段两闸不变，不另加确认密码；升级前快照、禁写窗口、防重入复用桌面同一套编排，网页端触发不改变桌面行为。桌面端的更新管理（设置页更新 tab、手动检查、下载进度）仍桌面专属，网页端只有「发现新版→点击升级」一条最小通路。

## Considered Options

- 维持 ADR-0003 原裁剪：手机上发现新版仍无能为力，"不开电脑屏幕随手记"的场景里升级永远断链——弃。
- 网页端全量更新管理（手动检查按钮、下载进度、更新页）：日常记录场景用不上，把管理复杂度搬进浏览器——弃，只放发现与确认升级。
- 升级前另加一道确认密码：已有令牌 + 受信网段双闸，持完整网址才算进门，再加一道只添麻烦——弃。

## Consequences

- CONTEXT.md「网页端」「桌面端」词条同步修订：更新移出"网页端没有"的列举。
- ADR-0003 其余裁剪（字典/备份/恢复/导出/设置）不动，"记录、不管理"的总纲仍成立，仅更新一点改为"一键升级"。
- 升级即服务本体重启，网页端会短暂断开；依赖 SSE 重连与版本比对自动恢复。
