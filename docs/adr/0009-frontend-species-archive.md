# 物种档案用前端静态档案包，饲养资料永不进数据库

2026-09 物种档案批次（12 份内置档案 + 图鉴页 + 自建物种）定下：物种饲养档案是随应用分发的只读参考资料，不是用户产生的数据。实现为前端静态档案包：构建期 glob 导入 src/data/species/*.json，一物种一文件、文件名 = key（拉丁名 slug）；加一份档案就是加一份 JSON，代码零改动，类型分组、冬眠筛选随之自动生效。饲养资料永不进数据库，窝表只存 species_key + 显示名快照。契约要点：类型（type）是档案数据，分组一律 distinct 动态得出，禁写死枚举；字段空字符串 = 查无实据，界面显示「暂无资料」，绝不填默认值；内置 key 用拉丁名 slug（无前缀），与自建 custom-N 命名空间隔离。Rust 侧 BuiltinSpecies 镜像清单（src-tauri/src/species.rs）与 JSON 同名同键，承担 v15 迁移的别名归组与 species_key 合法性校验——涉及 key 或别名的档案改动，两处须同步。

## Considered Options

- 档案进数据库表：文案每次修订都要写迁移，备份/恢复被参考资料撑大，而档案本就不是用户数据——弃。
- 前端 TS 常量硬编码：12 份档案混进代码，文案修订的 diff 埋在代码改动里——弃，JSON 一文件一物种，改文案就是改数据文件。
- 服务端/远端下发档案：单用户本地应用没有服务端，为参考资料加部署物不值——弃。

## Consequences

- 加新物种 = 加一份 JSON（外加 Rust 镜像清单补一行），零代码改动。
- 档案文案修订（如 2026-09-30 夜链的文案人化）直接改 JSON，不动库、不写迁移。
- 界面的分组枚举、筛选维度全部从档案数据动态推导，前端不存在需要与档案内容同步的写死清单。
