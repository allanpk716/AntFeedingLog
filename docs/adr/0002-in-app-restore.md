# 应用内整库恢复（推翻首发时"不做导入恢复"的决策）

首发（票 09，评审附录规则 11）刻意把 CSV/JSON 导出定位为"归档带走"，并明确"应用内不做导入恢复"，恢复 = 用户手动把备份的 .db 拷回数据文件夹。2026-09-18 用户提出要在应用内恢复数据。决定：做**整库恢复**（选一份备份整体替换当前数据），不做合并导入——合并要处理主键冲突、字典对齐、去重规则，复杂度远超单机单用户场景的收益。恢复带三道保险：恢复前自动备份当前库、预览备份摘要（几窝/几条/哪天的备份）、二次确认。

## Consequences

- 恢复是替换语义：旧数据全部消失，靠"恢复前自动备份"兜底反悔路径。
- `system.rs` 头注释与设置页帮助文案中"应用内不做导入恢复"的说法作废，需同步更新。
