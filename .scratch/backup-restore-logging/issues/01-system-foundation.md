# 票 01 · 系统底座：日志模块 + 异常退出标记 + 单实例

Spec：`docs/superpowers/specs/20260918-backup-restore-logging-spec.md`（D7/D8/D9/D10 日志与退出部分）

## What to build

应用的系统底座，让"出问题有地方查"成立：

1. **日志模块**：日志落数据目录 `logs/` 子目录，纯文本按天滚动，自动删超过 14 天的旧日志。记录错误（Tauri 命令失败、Rust panic——挂 panic 钩子、前端未捕获异常——转发到 Rust 落盘）与关键动作流水（本票先接：启动、正常退出；后续票接入备份/恢复/更新/提醒事件）。
2. **异常退出判定（运行标记）**：启动时写运行标记；清理接入全部可识别的优雅退出路径——托盘"退出"、应用内更新安装的重启前、主事件循环正常收尾（覆盖 OS 关机/注销的正常销毁序列）。下次启动发现标记残留 = 上次异常退出；无崩溃日志时显示"（无崩溃日志，疑强杀/断电）"。
3. **单实例**：接入 Tauri 单实例插件，第二实例启动时聚焦已有主窗口并退出（运行标记与后续备份账目的前提）。
4. **设置页日志区**：同页签新增"打开日志文件夹"按钮、"最近错误摘要"展示、"上次异常退出：时间+原因（或疑强杀/断电）"展示。

沿用仓库既有模式：纯函数核心（日志文件命名/滚动/清理/标记判定）与 Tauri/IO 解耦，cargo test 直测；命令壳在 lib 层。

## 验收标准

- [ ] panic（人为触发）后日志文件里有 panic 记录；下次启动设置页显示"上次异常退出"且带原因行。
- [ ] 模拟强杀（不清理标记直接结束进程）后重启：显示"上次异常退出：<时间>（无崩溃日志，疑强杀/断电）"。
- [ ] 托盘退出、OS 注销/关机、更新重启三条路径退出后重启：**不**误报异常退出。
- [ ] 双开第二个实例：不产生第二个窗口/进程常驻，已有窗口被聚焦。
- [ ] 日志按天滚动成多个文件；>14 天的旧日志被自动清理（单测以注入时钟/文件名验证清理逻辑）。
- [ ] 前端抛未捕获异常：落日志且应用不崩。
- [ ] "打开日志文件夹"能打开 logs 目录；最近错误摘要显示最近若干条错误。
- [ ] cargo test + 前端测试全绿；release profile 保持 unwind（不得引入 panic=abort）。
