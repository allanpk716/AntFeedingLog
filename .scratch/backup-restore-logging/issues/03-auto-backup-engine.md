# 票 03 · 自动备份引擎：触发 · 执行 · 保留淘汰

Spec：`docs/superpowers/specs/20260918-backup-restore-logging-spec.md`（D2/D3/D4 + D7 动作流水接入）

## What to build

自动备份的核心引擎（D2/D3/D4 的完整落地）：

1. **统一触发谓词（D2）**：`需要备份 ⇔ last_data_write_date > last_backup_date`，叠加 `开关开 ∧ 目录已设`。触发点两处：业务写入完成后（记录/窝/字典/冬眠的增删改；元数据写入不算）与应用启动时。业务写入后更新 `last_data_write_date`。
2. **时钟回拨钳制**：`last_backup_date` 晚于今日 → 视为无效清空；`last_data_write_date` 晚于今日 → 钳到今日。备份不停摆。
3. **备份执行协议（D3）**：拿库锁 → 库文件拷数据目录临时文件 → 释放锁 → 锁外把临时文件拷到备份目录 → 成功删临时文件并更新元数据；失败静默记失败（原因+时间）、清理临时文件、待下个触发点重试。
4. **保留淘汰（D4）**：只清理备份目录内匹配 `ant-feeding-log-backup-<8位日期>-<6位时间>.db` 且时间戳可解析的文件；按文件名内时间戳排序，超出保留份数删最旧；其他文件绝不触碰。
5. **动作流水**：备份成功/失败写日志（票 01 模块）。
6. **设置页联动**：上次备份状态接真数据（票 02 的展示位）。

## 验收标准

- [ ] 当日第一次业务写入后自动产生一份备份；当日后续写入不再重备（谓词追平）。
- [ ] 跨日后首次启动、当天尚无任何业务写入：**不**备份（无新数据谓词不成立）。
- [ ] 备份失败（目录不可写）后：当日后续写入与下次启动自动补跑；期间无弹窗。
- [ ] 时钟回拨场景（单测注入）：`last_backup_date` 未来化被清空、备份恢复运转；`last_data_write_date` 被钳制。
- [ ] 备份文件名含 `YYYYMMDD-HHMMSS`；同日两次（补跑场景）不互相覆盖。
- [ ] 保留淘汰：目录中放置手动备份（命名不同）与无关 `.db`/文档，超出 N 份后**只有**自动备份命名的文件被删、按文件名时间戳删最旧（单测断言无关文件原样存在）。
- [ ] 拷贝期间库锁只覆盖本地临时文件拷贝段（网络盘目标目录不阻塞业务命令——以慢速目录模拟测试锁窗口）。
- [ ] 目录未设或开关关：不产生任何备份动作。
- [ ] 成功/失败均写日志流水；设置页状态与实际一致。
- [ ] cargo test + 前端测试全绿。
