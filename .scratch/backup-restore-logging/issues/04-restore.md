# 票 04 · 恢复：四步协议 + 界面流程

Spec：`docs/superpowers/specs/20260918-backup-restore-logging-spec.md`（D5/D6/D10/D11 恢复部分）

## What to build

应用内整库恢复（替换语义，ADR-0002）：

1. **命令**：`restore_preview(path)` → 校验链通过则返回摘要 {备份日期、窝数、记录数、库内（旧）备份目录设置值}；否则返回可展示的拒绝原因。`restore_apply(path)` 重走校验后执行协议（TOCTOU 安全）。
2. **四步协议（D5）**：
   - 步骤 1 源校验与 staging：拒绝"源路径 == 当前库路径"；源文件复制为数据目录 `restore-staging-<时间戳>.db`，此后一切在临时库上进行。
   - 步骤 2 临时库校验：可打开（否则"这不是本应用的备份"）→ `PRAGMA integrity_check` ok（否则"备份文件已损坏"）→ schema 版本：旧版在临时库上跑迁移管线升级后复校；比当前程序新则拒绝（"这是未来版本的备份，请先升级应用"）。
   - 步骤 3 pre-restore 快照：当前库拷 `pre-restore-<时间戳>.db` 到数据目录，最多保留 3 份，超出删最旧（只匹配自家命名）。
   - 步骤 4 替换与重载：拿库锁 → 锁内"写新文件 + 原子改名"替换 → `Mutex` 下重建连接 → 广播各页刷新；重建失败重试 3 次（短退避）→ 仍失败保持新库文件并提示"恢复已完成，请重启应用"。
   - 失败语义：步骤 1–3 任一失败当前库零改动、清理 staging、报具体原因；替换先写后改名，中途失败原库未破坏。
3. **界面流程（设置页"从备份恢复"按钮）**：选文件（对话框默认定位备份目录，已设置时）→ 摘要预览（含备份内目录设置值与"备份设置保持当前值，不随恢复回滚"文案）→ 二段确认（与删除记录同待遇）→ 执行 → 刷新或重启提示。
4. **动作流水**：恢复执行（含来源文件）写日志。

## 验收标准

- [ ] 选正常备份 → 摘要显示窝数/记录数/备份日期/备份内目录值；确认后整库替换、界面当场刷新（或明确提示重启）。
- [ ] 选损坏文件 / 无关 `.db` / 未来版本备份 / 当前活动库自身 → 分别得到对应明确拒绝信息，当前库零改动。
- [ ] 旧版本 schema 备份（构造 v1 备份）→ 自动升级后可恢复。
- [ ] 恢复前自动产生 pre-restore 快照；第 4 次恢复时最旧的快照被清理（保留 3 份）。
- [ ] 步骤 1–3 注入失败（单测）：当前库字节级零改动、staging 被清理。
- [ ] 恢复后：业务数据=备份时刻；备份配置文件不变（D1）；提醒台账随库回滚。
- [ ] 摘要预览是最后防线（D6）：选错文件场景下摘要能暴露内容异常（0 窝 0 条等）。
- [ ] cargo test + 前端组件测试全绿（含恢复流程组件测试）。
