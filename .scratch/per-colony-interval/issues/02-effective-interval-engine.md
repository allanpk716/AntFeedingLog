# 票 02 · 有效周期解析接入提醒判定链(tiles + 提醒引擎)

## What to build
把每窝周期接入超期判定:某窝某操作的**有效周期** = 该窝每窝周期(若有)否则操作层建议间隔。卡片数据(tiles_for_colony)与按日提醒(compute_due_reminders)全部换用有效周期;喂食按 spec 钉死的判定式(设了每窝周期则不参与统一周期判定,食物层照旧 OR);超期口径严格大于。

## 验收标准
- [ ] 判定式(钉死,不得偏离):某操作超期 = `days_since_last > 有效周期`;喂食 = `[days > 有效周期] OR [任一食物 days(该食物) > 该食物周期]`,其中设了每窝周期的窝的操作层 OR 项=每窝周期(不再看统一周期),未设=统一周期;撤食(kind=follow)永不参与
- [ ] 边界:days == 有效周期 → 不红不发通知;days == 有效周期+1 → 红且当日进提醒
- [ ] 没设每窝周期的窝,一切行为与现状一致(登记类永不红;提醒类按操作层间隔);从未做过(days 为空)不产生提醒
- [ ] 冬眠静音、已结束不催、台账每日去重(每条每天最多一次、做了为止)全部照旧;通知文案中的周期值取该窝有效周期
- [ ] tiles 数据结构携带:有效周期与"距上次",足以让前端区分"设了每窝周期/未设"(字段命名与类型自洽,票 03 将消费;保留既有字段不删不改语义)
- [ ] 统计(stats.rs)不改动——若其查询与 tiles 无关则自然满足,不得顺手扩口径(D10 最小口径)
- [ ] cargo test 全绿(新增用例覆盖:设/未设、取代统一周期、食物层叠加、严格大于两侧边界、冬眠、已结束、从未做过、台账去重、撤食不受影响)
