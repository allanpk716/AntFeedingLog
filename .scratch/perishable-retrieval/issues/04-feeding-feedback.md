# 票 04 · 喂食提交反馈按分类分支 + 易腐标记

## What to build

打通"喂食提交时告知提醒安排"的端到端切片：FeedDialog 食物多选列表给易腐项加小记号；提交成功反馈按喂食分类给出正确文案，不承诺不会发生的事。

- **易腐记号**：食物多选列表中 `perishable=1` 的项加一个小标记（样式与现有列表一致，如角标/圆点）。
- **反馈文案分支**（依据票 01 落地的 Food DTO 字段 `perishable`/`retrievalHours` 与用户所选发生时刻）：
  - 所选含易腐且**全部有有效间隔**，且 `发生时刻 + min(所选易腐间隔) > 现在`（新鲜）→ "将于 X 小时后提醒撤食"（X = 最短间隔小时数）。
  - 所选含易腐且全部有有效间隔，但录入时已逾期（补录场景）→ "已逾期，明起每日提醒撤食"（不给将来时刻承诺）。
  - 所选含易腐但存在无有效间隔的（正常情况下被设置必填堵住，仅脏数据可达）→ 不显示撤食反馈句。
  - 所选不含易腐 → 无撤食反馈（现状不变）。
- 组件内实现判定逻辑（纯函数，便于测试）；不改后端。

## 验收标准

- [ ] 选面包虫（24h）提交 → 反馈含"将于 24 小时后提醒撤食"
- [ ] 面包虫+湿食(6h) → "将于 6 小时后提醒撤食"（取最短）
- [ ] 补录 3 天前的面包虫 → "已逾期，明起每日提醒撤食"
- [ ] 不选易腐 → 无撤食反馈句
- [ ] 食物列表易腐项带记号
- [ ] 新建 FeedDialog 组件测试覆盖上述分支
