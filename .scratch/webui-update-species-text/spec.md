# Spec: 网页端点击升级 + 物种档案文案人化

来源: .xcheck/20260930-133109/proposal.md(收敛稿) + 同环 decisions.md(D1~D10) + FINDINGS.md(F6~F10 低severity建议已择要纳入)。术语遵守项目 CONTEXT.md 词汇表。

## Problem Statement

单用户在受信网段用手机浏览器日常记录蚂蚁饲养,但程序升级只能回到电脑桌面端操作——手机上发现新版本毫无办法。同时,图鉴页的物种档案文案里混着大量来源考证括号（如「（多源）」「（文献+多源）」「（商家单源）」）和生硬的元话语（「低置信」「查无实据」），读起来像论文注脚,新手玩家看不懂重点。

## Solution(用户视角)

1. 手机网页端打开应用时,如果有新版本,顶栏出现一条横幅「有新版本 vX → 点击升级」;点开看到当前版本、新版本号和更新说明,点「确认升级」后电脑上的程序自动下载并重启,页面短暂断开后自动恢复并提示「已升级到 vX」。失败给原因和重试。横幅可关,关了本次会话不再出现。
2. 图鉴页 12 份物种档案的全部文案去掉来源括号、把「低置信/查无实据」说成自然话;数字、温度、价格、警告等事实内容一字不改。

## User Stories

1. 作为网页端用户,我想打开应用时就能看到"有新版本"的横幅,以便知道不用回电脑也能升级。
2. 作为网页端用户,我想在确认面板看到当前版本、新版本号与更新说明,以便放心点「确认升级」。
3. 作为网页端用户,我想确认后程序自动下载并重启、页面自动恢复并告诉我已升到哪个版本,以便全程不碰电脑。
4. 作为网页端用户,我想升级失败时看到具体原因并能一键重试,以便自行恢复。
5. 作为网页端用户,我想关掉横幅后本次会话不再被打扰,以便专心日常记录。
6. 作为图鉴页读者,我想档案文案没有来源括号、说法自然,以便直接读懂饲养要点——而事实信息(数字/温度/价格/警告/口径冲突/考证结论)一个不少。

## Implementation Decisions

**A. 服务端红点数据扩展(F1 修订① + F6)**
- 落库:在现有"远端可用版本号"存储的同一处,一并存 release 说明(notes);检查发现无新版/已最新时,清除版本号的同一处一并清 notes(notes 生命周期跟随 available),绝不外显陈旧 notes。
- 桌面端既有红点命令与事件负载形状(BadgeState{available})**不变**——扩展只加存储与新命令,不动桌面契约。

**B. 新只读命令(网页端白名单)**
- 返回 `{ available: bool, version: string|null, notes: string|null }`;无参数;进 WEBUI_COMMANDS 白名单注册表与 webui_args 校验链(deny-by-default 不变)。
- 当前版本号不经该命令——前端自取 bundle 的 package.json(桌面/网页端同 bundle 的既有模式)。

**C. 升级触发命令(网页端白名单)**
- 复用服务端既有升级确认流编排(复查→下载→拉安装器;升级前快照、禁写窗口、CONFIRM_IN_FLIGHT 防重入全部照旧);返回既有安装结果契约(install_started{version} / install_failed{version,message});Err=检查失败类(含"远端已没有比当前更新的版本"、防重入拒绝串)。
- 桌面端升级命令与入口一律不动;网页端触发不改变桌面行为。

**D. 网页端前端(浏览器模式专属;桌面端不渲染)**
- 外壳层横幅组件:挂载时调一次新只读命令;available=true 才显示;× 关闭后会话内不再出现(不落任何持久存储);不设常驻红点。
- 确认面板:当前 vX(取 package.json)→ 新版 vY + notes(notes=null 时省略说明区,F10)。
- 升级状态机:待确认 → 确认中(命令在途)→ 下载等待态(文案"正在下载升级包,应用将自动重启,本页会短暂断开——恢复后自动刷新",不展示百分比)→ 重启占位("正在重启中…")。
  - 出口1:install_failed 响应在 HTTP 生命周期内返回 → 切回失败态,红色轻提示带原因 + 重试按钮(F3a)。
  - 出口2:确认升级起 10 分钟内 SSE 未重连成功(F7 取值)→ 占位切换为"升级可能未完成,请到电脑端确认,或稍后刷新本页",不再转圈、页面可手动刷新(F3b)。
  - 出口3:复查无新版(Err 文案"远端已没有比当前更新的版本")→ 红色轻提示带该原因,**不弹重试按钮**(F8),重读红点、收横幅,不进下载态;该分支以复查结果对齐红点落库(F6)。
  - 出口4:SSE 重连成功 → 页面自动刷新(既有 versionSync 机制)→ sessionStorage 记录的目标版本与当前 bundle 版本比对:相等弹「已升级到 vY」成功轻提示并清记录;旧版本回来了不弹、清记录(F4/修订④)。
  - 防重入拒绝(现有固定串)→ 平静提示"安装正在进行中,请稍候",不出重试(复用现有文案纯函数口径)。
- 检查失败/下载失败/安装失败一律:红色轻提示带原因 + 重试按钮;不提供手动下载引导。
- 合规:全局唯一 toast 模块(操作反馈规范)、全局唯一 LoadingHint(加载态规范)、组件与同名 *.test.ts 同目录。

**E. 物种档案文案改写(功能二)**
- 范围:src/data/species/ 全部 12 份 JSON 全字段。
- 删纯来源括号:（多源）（文献）（文献+多源）（商家单源）（商家口径）（原调研）（属级估计）（属级）（经验）（属通病）（单源经验）;括号内是内容的保留(如「（新后小群，原调研）」→「（新后小群）」)。
- 改元话语:「低置信」→「各家说法不一/不太靠得住」类自然说法;「查无实据」→「没有可靠数据」。
- 事实一字不虚:数字、温度、价格、警告、口径冲突、考证结论全保留,只顺句子;空字符串=「暂无资料」契约不动。
- 同步:speciesProfiles.ts 头注释删「有据值行内标注来源档」条;SpeciesGuidePage.vue 避坑名单香斑条删「（多源一致）」;避坑其余 6 条与通用饲养知识七主题不动;docs/调研养蚂蚁的文档/ 原始存档不动。

**F. 文档与决策记录**
- CONTEXT.md:「网页端」「桌面端」两词条把「更新」移出"网页端没有"清单(其余系统管理不动)。
- docs/adr/0009:回填"前端静态物种档案包"决策(代码 speciesProfiles.ts 已引用该编号,文件从未写;内容按现状写实:构建期 glob 导入、一物种一文件、饲养资料永不进数据库)。
- docs/adr/0010:网页端升级入口(部分反转 ADR-0003 中"更新留桌面端"一点;理由:升级结果落在服务器侧正是要的行为;令牌+受信网段两闸不变;记录 A/B/C/D 的边界)。

## Testing Decisions

- 升级状态机:纯函数/组件单测覆盖四条路径——install_failed 切回失败态、SSE 超时兜底切换、复查无新版收横幅、sessionStorage 比对弹成功提示;失败/防重入文案沿用现有纯函数口径。
- Rust:红点 notes 落库/随清单测(照 updater.rs 既有注入式测试先例);新只读命令与升级触发命令的白名单路由 + 校验 + 返回形状(与桌面 invoke 同形)测试(照 webui_server.rs 既有白名单测试先例);"其余更新类命令仍 deny-by-default 404"守护测试。
- 物种档案:契约测试更新 + 新增全量扫描断言——12 份 JSON 任意字段不得残留 11 种来源括号标记与「低置信」「查无实据」两字符串(F9);交付晨报附逐文件 diff 位置供用户过目(F5)。
- 全量门槛:vitest 全绿、vue-tsc 0 错误、cargo test 通过(既有 1 例端口占用环境例不计)。
- 真机冒烟(浏览器/手机点一遍横幅→确认→断线→恢复)由用户执行,代码层以单测覆盖状态机。

## Out of Scope

- 网页端手动"检查更新"按钮、下载进度百分比、完整"更新管理"页。
- 物种档案的任何事实改动、新增物种、调研存档改动。
- 桌面端升级入口/红点体系的任何变更。
- 自动合并分支——合并永远由用户决定。
