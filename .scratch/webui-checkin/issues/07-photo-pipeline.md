# 票 07 · 照片管线与桌面上传

规格:Implementation Decisions E;User Stories 9/11

## What to build

- 上传校验链(桌面/网页同一套纯核):单张压缩前 ≤15MB、单次 ≤9 张、格式白名单 JPEG/PNG/WebP、**解码前先校验头部宽高与总像素上限**(防解码炸弹)、仅静态图、完整解码后重编码(统一 JPEG 长边 2048 质量≈85,即清除全部 EXIF 含 GPS)。
- 写入协议:ensure `photos/<colonyId>/` → 写 `photos/<colonyId>/.tmp-<uuid>`(fsync)→ **同目录**原子 rename 为 `<uuid>.jpg` → 库事务插元数据并提交;失败路径:rename 后插库失败→删文件再报错;自动备份触发以元数据提交成功为准。
- 落盘文件名一律服务端 UUID;库存相对路径;客户端文件名只进备注。
- 删除顺序:**先库事务删元数据提交,再删文件**;文件删除失败仅产生孤儿,不回滚库。
- 孤儿巡检:启动/恢复后把库无引用文件移入 `photos/.orphan-<时间戳>/`(移动非删除);设置页"查看并清理孤儿照片"。
- 缺图占位:库引用文件缺失→占位符+提示,不崩溃。
- 桌面巢况 UI:时间线照片选择上传、网格展示、删除登记连带删照片。

## 验收标准

- [ ] 各断点失败注入(rename 后插库失败等)不留半截状态
- [ ] 解码炸弹样本(小文件巨尺寸头)被拒;GPS EXIF 清除实测
- [ ] 删除顺序测试:文件删失败→孤儿,库不回滚
- [ ] 孤儿隔离与清理入口可用;缺图占位
- [ ] 桌面端到端:选文件→压缩落盘→时间线展示
- [ ] 测试齐,既有全绿
