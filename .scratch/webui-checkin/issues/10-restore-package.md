# 票 10 · 数据包恢复(中断可续)与旧裸库兼容

规格:Implementation Decisions F(恢复/失败语义);User Stories 14/15/17

## What to build

- 恢复(数据包):读 manifest→格式版本检查(未来拒)→逐文件 SHA256 校验→**按 zip 实际条目元数据做磁盘空间预检(峰值 1.2×)**→解包到暂存目录(**严格路径 grammar:仅允许清单内 `[A-Za-z0-9_-]+/[A-Za-z0-9_-]+\.jpg` 形态;拒绝反斜杠/冒号/绝对路径/`..`/符号链接/重复条目/清单外文件**)→库走既有 staging 校验链(integrity+迁移)→**包照片集合覆盖库内引用校验(缺失即拒绝恢复)**→pre-restore 快照(升级为数据包,保留 3 份)→锁内换库→暂存照片逐文件 rename 落位→清退非清单文件→广播无条件刷新。
- **失败不变量:任何一步失败,当前库与 photos/ 均未被破坏**;库替换后中断→新库引用照片已在暂存区就绪,可续(重试/重启继续落位);清退最后,残留即孤儿由巡检收。
- 恢复(旧裸库 .db):照既有 staging 迁移链;photos/ 不动;恢复后孤儿治理。
- 恢复摘要:几窝/几条/照片几张(或"不含照片")。

## 验收标准

- [ ] 暂存/换库/落位/清退各断点注入:现状不破坏、可续、无半截
- [ ] 恶意 zip(穿越/ADS/驱动器相对/重复/符号链接/清单外)一律拒
- [ ] 包照片集合不覆盖库引用→拒绝恢复并报人话原因
- [ ] 旧裸库恢复回归通过;快照为新格式
- [ ] 摘要正确;恢复完成两端无条件刷新
- [ ] 测试齐,既有全绿
