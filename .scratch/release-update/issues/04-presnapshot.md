# 票 04 · 升级前快照：onBeforeExit 挂点 + 防覆盖命名 + 禁写窗口

## What to build

用户确认升级后的数据安全网：

- 快照挂 updater 插件 `on_before_exit` 钩子执行（退出前、数据流已停），复用票 09 既有"短暂拿锁挡并发写 → 拷贝单 .db 文件"机制（journal_mode=DELETE 下拷贝即完整快照）。
- 文件名**防覆盖**：`backups/pre-update-v<当前版本>-<yyyymmdd-hhmmss>.db`——同一版本重试/重装不再覆盖旧快照。
- 快照完成后进入**禁写状态**直到安装流程结束（进程即将退出，期间任何写请求直接拒绝），保证快照不落后于实际数据库。
- 快照失败**不阻塞**升级，但把失败状态记录下来（供诊断/晨报）。

## 验收标准

- [ ] cargo test：快照文件名含源版本+时间戳，同版本两次快照并存不覆盖
- [ ] cargo test：禁写状态生效（禁写后写请求被拒；快照前正常写不受影响）
- [ ] cargo test：快照失败不产生错误中断（升级流程继续，状态可查）
- [ ] 快照产物可被应用正式打开通道重开（沿票 09 测试先例）
- [ ] 复用既有备份函数而非另写一套拷贝逻辑
