# 票 05 · 升级执行与失败兜底：确认流 + pending 标记 + 启动检测

## What to build

用户确认升级后的完整执行链与失败兜底：

- **确认流**：`mark_pending_install(新版本号)`（持久化标记，先于下载写入）→ 下载 → 安装（插件 install()，NSIS 静默）。
- **启动检测**（已知残余风险的兜底）：应用启动时对比"上次标记的待安装版本"与当前运行版本——
  - 当前版本 ≥ 待安装版本 → 升级成功：清标记（可选轻提示"已更新到 vX"）；
  - 当前版本仍旧版 → 上次升级未完成：清标记并提示"上次升级未完成"，给重试（再走确认流）或手动下载引导。
- 状态标记持久化在应用数据目录（如 JSON 小文件），不进数据库（数据库可能正被迁移）。
- 对外 command：`confirm_and_install`（含进度回调）、`get_update_state`（查询 pending 标记与结果判定）。

## 验收标准

- [ ] cargo test：pending 标记写入/清除生命周期（确认时写、成功后清、失败后清+可查）
- [ ] cargo test：启动判定逻辑——标记版本==当前版本（成功路径）/ 标记版本>当前版本（失败路径）/ 无标记（正常路径）三态
- [ ] cargo test：标记文件损坏/缺失时不影响启动（按无标记处理）
- [ ] 确认流顺序有测试锚点：先标记后下载（下载失败时标记仍在，启动检测才能发现"想升没升成"）
