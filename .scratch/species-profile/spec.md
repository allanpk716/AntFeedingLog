# 物种档案（Species Profile）实施规格

> 来源：`.xcheck/20260929-164029/proposal.md`（评审收敛稿 rev1）+ 同环 decisions.md（D1~D19）+ FINDINGS.md（F1~F9）。
> 术语遵守 CONTEXT.md 词汇表（物种/物种档案/物种类型/图鉴/新手推荐）；架构决议见 docs/adr/0009（前端档案包，不走数据库字典）。

## Problem Statement

窝的物种目前是自由文本：拼写随意、无结构、无法筛选，也无法承载饲养资料。饲养者想要：每窝关联到一个有拉丁名/中文俗名/类型/冬眠需求/饲养参数/发展预期/风险敏感度的**物种档案**；图鉴页看新手推荐与全部资料；选择物种时可筛选可搜索；资料查无实据时如实显示"暂无资料"而不是编数字。

## Solution

内置 12 种蚂蚁（收获蚁 4 + 弓背蚁 8）每种一份 JSON 档案，随应用发布（前端静态档案包，加物种=加文件零代码）；窝表存 `species_key` + 显示名快照；旧自由文本在 v15 迁移中按别名归组，匹配不上的自动转自建物种，绝不丢数据。图鉴页（双端）承载新手推荐、全部档案、通用饲养知识；窝表单的选择器按类型/冬眠筛选+搜索+悬停摘要+内联自建；自建物种在设置·物种 tab 管理。内容按隐私规则清洗（无个人位置/场景信息）。

## User Stories

1. 作为饲养者，我想给每窝蚂蚁选定一个物种（含拉丁名与中文俗名），以便窝卡片清晰展示养的是什么。
2. 作为饲养者，我想按类型（收获蚁/弓背蚁/自定义…随档案扩充自动成组）和冬眠需求（冬眠/浅冬眠/不冬眠）筛选物种、按中文名/拉丁名/别名搜索，以便快速定位。
3. 作为饲养者，我想悬停物种名看到一句话摘要（温度/食物/冬眠三要素），以便不翻资料就能对照。
4. 作为饲养者，我想在选不到时内联自建一个物种（名字必填、类型默认"自定义"可改），以便记录档案之外的蚂蚁。
5. 作为饲养者，我想在图鉴页看到新手推荐（按冬眠/不冬眠两条路线陈列）与避坑提醒（含"暴毙天王"类点名），以便第一次买蚁不踩坑。
6. 作为饲养者，我想在图鉴页逐个展开每个物种的完整档案（饲养参数/发展预期/风险敏感度/购买提醒），查无实据的字段如实显示"暂无资料"，以便建立准确预期。
7. 作为饲养者，我想在图鉴页底部看到通用饲养知识（糖水怎么兑/白水与糖水/交哺原理/产卵膏拆穿/蛋白质投喂/报警信号速查/新后到手两周），以便日常照看有据可查。
8. 作为饲养者，我希望升级后老窝的物种自由文本自动归组（正式中文名/俗名别名/拉丁名，trim+大小写不敏感精确匹配），匹配不上的自动变成自建物种且名字原样保留，以便数据不丢、不用手工重填。
9. 作为饲养者，我希望窝卡片徽章始终显示物种的当前中文名（悬停看"拉丁名·类型·冬眠需求"），以便物种改名后显示依然正确。
10. 作为饲养者，我想在设置里管理自建物种（改名/删除；有窝引用时禁删），以便维护清单。
11. 作为手机网页端用户，我想在网页端给窝选物种（含自建物种清单）并浏览图鉴，以便不在电脑前也能用。
12. 作为将来的自己，我想新增一种蚂蚁时只添加一份 JSON 档案文件（分组等随之自动生效，软件代码零改动），以便扩充不打断。

## Implementation Decisions

**档案包（前端）**：`src/data/species/` 一物种一 JSON（key=拉丁名 slug），构建期 glob 导入；schema=顶层 21 字段 + growth 组 10 字段 + risks 组 6 字段 + careNotes（完整示例见 proposal §3.2）；`type` 是档案数据（界面按 distinct 动态分组，禁写死枚举）；`hibernation` 三值（冬眠/浅冬眠/不冬眠）供筛选；空字符串字段=界面"暂无资料"；有据值行内标注来源档（文献/多源/商家/经验/属级估计）。

**key 契约（长期数据契约）**：内置 key=拉丁 slug（无前缀）；自建 key=`custom-<自增id>`（AUTOINCREMENT，永不复用永不改变）；`species_key` 一律存 key 绝不存名字；解析规则前后端统一——`custom-` 前缀→查自建表，否则→查内置档案，都解析不到→回落显示名快照；内置档案 key 不得以 `custom-` 开头（作者规则）。

**自建物种表**：id AUTOINCREMENT / key TEXT UNIQUE / name TEXT UNIQUE / type（默认"自定义"）/ created_at。名字唯一（迁移同名归并 INSERT OR IGNORE）；删除按 key 查引用守护（被引用禁删）；改名只改 name 列并级联刷新引用窝的快照列（单条 UPDATE），绝不改 key。

**迁移 v14→v15（轻迁移，不重建表）**：colony 加 `species_key TEXT NULL`；别名表一次性内置在迁移里（正式中文名+俗名别名+拉丁名→key；trim+大小写不敏感精确匹配）；匹配成功→key+快照规范化为 cnName；未匹配非空→自动建自建物种（快照=原文本原样）；空→两列皆空；旧 `species` 列保留为显示名快照。

**渲染**：窝卡片徽章按 key 实时解析（内置档案∪自建表）优先，不可解析回落快照，两皆空不显示；悬停 title="拉丁名 · 类型 · 冬眠需求"。

**命令面**：桌面端新增自建物种 list/create/rename/delete（引用守护）；create/update_colony 扩展 species_key；网页端白名单加自建清单只读命令，create/update_colony 的 webui_args 参数镜像同步增加 species_key 校验；自建写操作仅桌面端。

**图鉴页**：顶部 tab 排最后（首页/统计[桌面]/照片/日志/图鉴），双端；结构=新手推荐区（4 推荐位：针毛收获蚁/红头收获蚁/中亚弓背蚁/拟光腹弓背蚁，按冬眠/不冬眠两路线；避坑提醒含排除 7 种与香斑点名）→ 全部档案（类型分组、逐个展开、空字段"暂无资料"、难度★、惊吓新后/成群两档）→ 通用饲养知识静态区块（不进档案包）。

**选择器**：替换 ColonyFormDialog 自由文本；类型分组+冬眠筛选+搜索+悬停一句话摘要+＋自建内联；物种可不填。

**内置数据与内容口径**：12 种清单/命名裁决（正式中文名+俗名进 aliases：中亚弓背蚁[原"突厥"]/瑕疵弓背蚁[原"统领"]/"热带黑金"弃用）/冬眠口径修正（针毛浅冬眠、红头浅冬眠+新后必须越冬、工匠浅冬眠）/难度（香斑★★★）见 proposal §3.3；数据唯一来源=三份调研存档（`.xcheck/20260929-161746/research-*.md`）；隐私清洗规则见 proposal §6（删个人位置/场景，保留物种分布与价格，本地化结论改条件式）。

**UI 规范（全局强制）**：写操作无天然反馈→全局唯一 toast；异步读取→全局唯一 LoadingHint；内存数据即时渲染。备份为整库文件快照，新增表/列天然覆盖，无需备份改动。

## Testing Decisions

- **Rust（外部行为）**：v15 迁移测试——别名归组（正式名/俗名/拉丁名/大小写/trim）、未匹配转自建（同名归并、名字原样）、快照规范化、空保持空、幂等；命令测试——自建 CRUD、删除引用守护、改名级联刷新快照、key 不可变。沿 db.rs 既有 per-version 内存库测试先例。
- **前端（外部行为）**：档案 loader（12 种、类型 distinct、空字段）；选择器（分组/筛选/搜索/悬停摘要/自建内联/可不填）；图鉴页（推荐区路线陈列/档案渲染/"暂无资料"/通用知识区块）；窝卡片徽章（实时解析优先/快照兜底/悬停）；设置·物种 tab（改名/删除守护/toast）。沿组件同目录 `*.test.ts` 先例；既有测试全量不回归。

## Out of Scope

- 排除的 7 种蚂蚁不做档案不可选（只文字提及）；通用饲养知识不进档案包；内置物种无停用开关、不可删改；物种不进日志筛选/统计维度；外部文件夹热加载；表单物种不强制必填。
- **零代码承诺边界**：加 JSON=新物种立即可选/可展示/可记录；不承诺历史自建物种或旧快照自动重新归组到新内置档案。
